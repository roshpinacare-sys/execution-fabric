# ממשק הפעלה מאוחד לכלי הארסנל בלוח המשימות

# הצעה: ממשק הפעלה מאוחד לכלי הארסנל בלוח המשימות

## הבעיה
כרגע צי הכלים (`/api/arsenal`) קיים כרשימה סטטית. כדי להשתמש בכלי, המפעיל צריך:
1. לצאת מלוח המשימות
2. לקרוא תיעוד נפרד
3. להריץ ידנית דרך API/CLI
4. לעקוב אחרי התוצאה במקום אחר

זה יוצר חיכוך גבוה ושובר את זרימת העבודה הרציפה.

## הפתרון המוצע
הוספת **לשונית "כלים" / אזור צדדי** בלוח המשימות (`/tasks`) עם:

### 1. קטלוג כלי אינטראקטיבי
- רשימה מסוננת לפי קטגוריה (בנייה, בדיקה, פריסה, ניטור, ניתוח)
- כל כלי מציג: שם, תיאור קצר, פרמטרים נדרשים (JSON Schema), סטטוס זמינות
- חיפוש והשלמה אוטומטית

### 2. טופס הפעלה מובנה
- טופס דינמי שנבנה מה-JSON Schema של הכלי
- ולידציה בזמן אמת של פרמטרים
- כפתור "הרץ" עם אינדיקטור טעינה
- אפשרות לשמירת פריסטים (presets) לשימוש חוזר

### 3. מעקב הרצות (Execution History)
- טבלה עם: כלי, פרמטרים, סטטוס, משך, זמן התחלה/סיום, קישור לתוצאה/לוג
- סינון לפי כלי/סטטוס/טווח זמן
- כפתור "הרץ שוב" עם אותם פרמטרים

### 4. תצוגת תוצאות עשירה
- פאנל צדי/מודאלי עם: פלט טקסט, JSON מעוצב, קבצים מצורפים, מדדי ביצוע
- אפשרות ייצוא/שיתוף תוצאה
- קישור ישיר ליצירת משימת המשך מהתוצאה

### 5. אינטגרציה עם שרשרת המשימות
- כל הרצת כלי נרשמת כמשימה ב-Ledger (סוג `TOOL_EXECUTION`)
- מאפשר קישור שרשרת: משימה → כלי → תוצאה → משימת המשך
- תומך ב-retry אוטומטי על פי מדיניות הכלי

## מימוש טכני

### Frontend (Task Board)
```typescript
// רכיב חדש: ArsenalPanel.tsx
interface ToolSpec {
  id: string;
  name: string;
  description: string;
  category: 'build' | 'test' | 'deploy' | 'monitor' | 'analyze';
  parameters: JSONSchema7;
  returns: JSONSchema7;
  timeoutMs: number;
  retryPolicy?: RetryPolicy;
}

interface ExecutionRecord {
  id: string;
  toolId: string;
  parameters: Record<string, unknown>;
  status: 'pending' | 'running' | 'completed' | 'failed';
  startedAt: string;
  completedAt?: string;
  durationMs?: number;
  result?: unknown;
  error?: string;
  ledgerHash?: string;
}
```

### Backend API Extensions
```typescript
// GET /api/arsenal/specs - מחזיר מפרט מלא של כל הכלים
// POST /api/arsenal/execute - מפעיל כלי עם פרמטרים
// GET /api/arsenal/executions - היסטוריית הרצות עם סינון
// GET /api/arsenal/executions/:id - פרטי הרצה בודדת
// POST /api/arsenal/executions/:id/retry - הרצה חוזרת
```

### Ledger Integration
```typescript
// סוג רשומה חדש
interface ToolExecutionEntry {
  type: 'TOOL_EXECUTION';
  toolId: string;
  operator: string;
  parameters: Record<string, unknown>;
  resultHash: string; // hash של התוצאה המלאה
  durationMs: number;
  status: 'success' | 'failure';
  parentTaskId?: string; // קישור למשימה שיזמה את ההפעלה
}
```

## תועלות מדידות
| מדד | לפני | אחרי (יעד) |
|------|------|-------------|
| זמן מהחלטה להפעלה עד הרצה | ~5-15 דק' | <30 שניות |
| שגיאות פרמטרים ידניות | ~15% | <2% |
| מעקב אחרי תוצאות | ידני/מפוזר | אוטומטי/מאוחד |
| יכולת ביקורת (audit) | חלקית | מלאה בשרשרת |
| שימוש חוזר בפריסטים | לא קיים | נתמך |

## שלבי מימוש
1. **שבוע 1**: הרחבת `/api/arsenal` עם `specs` ו-`execute` endpoint
2. **שבוע 2**: רכיב `ArsenalPanel` בלוח המשימות + טופס הפעלה דינמי
3. **שבוע 3**: היסטוריית הרצות + תצוגת תוצאות + אינטגרציית Ledger
4. **שבוע 4**: פריסטים, retry policy, בדיקות קצה-לקצה

## סיכונים ומיתון
- **כלים ארוכי-ריצה**: תמיכה ב-WebSockets/SSE לעדכוני התקדמות בזמן אמת
- **כלים עם הרשאות**: בדיקת הרשאות לפני הפעלה (RBAC קיים)
- **עומס על API**: rate limiting פר-כלי ופר-משתמש
- **תאימות לאחור**: API הקיים נשאר ללא שינוי, רק מרחיבים
