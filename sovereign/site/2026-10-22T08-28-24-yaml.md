# מנגנון הפעלה דקלרטיבי לרכיבי צי-הכלים דרך הגדרות YAML

# הצעה: מנגנון הפעלה דקלרטיבי לרכיבי צי-הכלים דרך הגדרות YAML

## הבעיה
כיום הפעלת רכיבים מצי-הכלים דורשת כתיבת קוד הפעלה ייעודי (scripts, wrappers, נקודות כניסה). כל שינוי בזרימה — הוספת שלב, שינוי פרמטרים, מדיניות retry — מחייב שינוי קוד, בנייה מחדש ופריסה. זה מאט איטרציות, מגדיל שטח פגיעה ומקשה על ביקורת.

## הפתרון המוצע
ממשק הפעלה דקלרטיבי מבוסס קובצי **YAML** שמגדירים:
- **פיפליין** — רשימה סדורה של שלבים (רכיבים מהארסנל או פעולות מובנות).
- **קלט/פלט** — מיפוי שדות בין שלבים (JSONPath / jq-like).
- **מדיניות שגיאות** — `retry`, `fallback`, `continue-on-error`, `timeout`.
- **סביבה** — משתנים, סודות (הפניה לכספת), הגדרות ריצה.
- **מטא-דאטה** — תיאור, גרסה, בעלים, תגיות חיפוש.

מנוע הרצה יחיד (`pipeline-runner`) קורא את ההגדרה, מאמת סכימה, ומבצע את הפיפליין עם לוגינג מובנה, מדדים ושרשרת-אמת.

## דוגמת הגדרה (`pipelines/nightly-health.yaml`)
```yaml
version: "1.0"
name: "nightly-health-check"
description: "בדיקת בריאות לילית מלאה עם דיווח לקונסולה"
owner: "night-shift"
tags: ["health", "nightly", "console"]
env:
  VAULT_REF: "sovereign/health/tokens"
steps:
  - id: fetch-metrics
    component: "metrics-collector"
    input:
      scope: "system"
      interval: "24h"
    output: "metrics.raw"
    retry:
      attempts: 3
      backoff: "exponential"
  - id: analyze
    component: "health-analyzer"
    input:
      data: "{{metrics.raw}}"
      thresholds: "{{env.HEALTH_THRESHOLDS}}"
    output: "analysis.result"
    timeout: "120s"
  - id: render-console
    component: "console-renderer"
    input:
      template: "health-dashboard"
      data: "{{analysis.result}}"
    output: "console.payload"
    continue-on-error: true
  - id: persist
    component: "ledger-writer"
    input:
      payload: "{{console.payload}}"
      chain: "health"
    retry:
      attempts: 2
```

## יתרונות מדידים
| מדד | לפני | אחרי (יעד) |
|------|------|-------------|
| זמן הוספת שלב לפיפליין קיים | ~45 דק׳ (קוד+בנייה) | <2 דק׳ (עריכת YAML) |
| שטח קוד הפעלה ייעודי | ~2,300 שורות | ~300 שורות (מנוע בלבד) |
| כיסוי בדיקות לפיפליינים | 0% (אין הגדרה נפרדת) | 100% (סכימה + הרצה) |
| יכולת ביקורת (audit) | קשה — קוד מפוזר | מלאה — הגדרה יחידה, חתומה בלדג׳ר |

## תוכנית מימוש (3 איטרציות)
1. **סכימה + ולידציה** — JSON Schema ל-YAML, כלי `pipeline-lint` בקונסולה.
2. **מנוע הרצה מינימלי** — הרצת שלבים סדרתית, מיפוי קלט/פלט, retry/timeout בסיסי.
3. **אינטגרציה מלאה** — לוגינג ללדג׳ר, מדדים ל-/api/metrics, תמיכה בסודות דרך VAULT_REF, UI בקונסולה לצפייה/הרצה.

## סיכונים והפחתה
- **סיכון**: מורכבות מיפוי נתונים בין שלבים.
  **הפחתה**: ספריית ביטויים מינימלית (JSONPath), דוגמאות מקיפות, בדיקות יחידה לכל אופרטור.
- **סיכון**: הרשאות ריצה של רכיבים שרירותיים.
  **הפחתה**: רשימת רכיבים מותרים (allowlist) בקובץ מדיניות נפרד, חתום בלדג׳ר.
