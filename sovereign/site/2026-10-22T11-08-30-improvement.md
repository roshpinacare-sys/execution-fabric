# ממשק הפעלה מאוחד לצי-הכלים: הרצת פעולות ארסנל ישירות מלוח המשימות

# הצעה: ממשק הפעלה מאוחד לצי-הכלים

## הבעיה
כרגע צי-הכלים (`/api/arsenal`) קיים כ-API נפרד, ולוח-המשימות (`Dispatch → Workers`) מנהל משימות בנפרד. מפעיל שרוצה להריץ כלי (למשל: סריקת קוד, בדיקת בריאות, פריסת סביבה) צריך לעבור בין מסכים, להעתיק מזהים, ולהפעיל ידנית — מה שיוצר חיכוך, טעויות אנוש, וניתוק בין "מה תוכנן" ל-"מה בוצע".

## הפתרון המוצע
להוסיף לכל כרטיס משימה בלוח-המשימות כפתור **"הפעל כלי"** (סמל ⚙️ או 🔧) שפותח מודל צדדי (Side Panel) עם:

1. **רשימת כלים זמינים** — נשלפת דינמית מ-`GET /api/arsenal` (שם, תיאור, גרסה, פרמטרים נדרשים)
2. **טופס פרמטרים דינמי** — נבנה אוטומטית מה-schema של הכלי (JSON Schema → שדות קלט: טקסט, בחירה, בוליאני, קובץ)
3. **כפתור הרצה** — שולח `POST /api/arsenal/execute` עם `{ toolId, params, taskId }`
4. **תצוגת סטטוס בזמן אמת** — polling על `GET /api/arsenal/executions/{id}` עד סיום
5. **רישום אוטומטי בשרשרת-אמת** — בסיום (הצלחה/כישלון) נכתב בלוק ל-Ledger עם:
   - `taskId`
   - `toolId`
   - `params` (מוצפן אם רגיש)
   - `result` (סיכום + קישור ללוג מלא)
   - `executedBy` (מפעיל נוכחי)
   - `timestamp`

## למה זה ערך גבוה
- **סגירת לולאה**: משימה ← כלי ← תוצאה ← תיעוד — הכל בזרימה אחת
- **אפס קוד חדש בצד-שרת**: משתמש ב-API קיים של Arsenal ו-Ledger
- **מדיד**: זמן ממחשבה-להרצה יורד מ-דקות לשניות; שגיאות העתקה נעלמות
- **ניתן להרחבה**: כל כלי חדש ב-Arsenal מופיע אוטומטית — בלי שינוי ב-UI

## תכנית מימוש (3 שלבים)

### שלב 1: הרחבת API Arsenal (אם חסר)
```typescript
// POST /api/arsenal/execute
interface ExecuteRequest {
  toolId: string;
  params: Record<string, any>;
  taskId?: string; // אופציונלי — לקישור למשימה
}

interface ExecuteResponse {
  executionId: string;
  status: 'queued' | 'running';
}

// GET /api/arsenal/executions/:id
interface ExecutionStatus {
  id: string;
  toolId: string;
  status: 'queued' | 'running' | 'completed' | 'failed';
  result?: any;
  error?: string;
  startedAt: string;
  finishedAt?: string;
}
```
*אם כבר קיים — דילוג לשלב 2.*

### שלב 2: רכיב UI — `ArsenalLauncher` (React/TSX)
```tsx
// components/tasks/ArsenalLauncher.tsx
import { useState } from 'react';
import { fetchArsenalTools, executeTool, pollExecution } from '@/lib/arsenal-api';

interface Props {
  taskId: string;
  onExecutionComplete: (result: ExecutionResult) => void;
}

export function ArsenalLauncher({ taskId, onExecutionComplete }: Props) {
  const [tools, setTools] = useState<Tool[]>([]);
  const [selectedTool, setSelectedTool] = useState<Tool | null>(null);
  const [params, setParams] = useState<Record<string, any>>({});
  const [execution, setExecution] = useState<ExecutionStatus | null>(null);
  const [loading, setLoading] = useState(false);

  // טעינת כלים בפתיחה
  useEffect(() => {
    fetchArsenalTools().then(setTools);
  }, []);

  const handleExecute = async () => {
    setLoading(true);
    const { executionId } = await executeTool({ toolId: selectedTool!.id, params, taskId });
    const final = await pollExecution(executionId);
    setExecution(final);
    onExecutionComplete(final); // יעדכן את כרטיס המשימה
    setLoading(false);
  };

  if (!selectedTool) {
    return (
      <select onChange={e => setSelectedTool(tools.find(t => t.id === e.target.value))}>
        <option value="">בחר כלי מהארסנל</option>
        {tools.map(t => <option key={t.id} value={t.id}>{t.name} — {t.description}</option>)}
      </select>
    );
  }

  // טופס פרמטרים דינמי לפי JSON Schema
  const schema = selectedTool.inputSchema;
  return (
    <div className="arsenal-launcher">
      <h4>{selectedTool.name}</h4>
      <p>{selectedTool.description}</p>
      {Object.entries(schema.properties).map(([key, prop]) => (
        <div key={key} className="form-field">
          <label>{prop.title || key}</label>
          {prop.type === 'boolean' ? (
            <input type="checkbox" checked={params[key]} onChange={e => setParams({...params, [key]: e.target.checked})} />
          ) : prop.enum ? (
            <select value={params[key]} onChange={e => setParams({...params, [key]: e.target.value})}>
              {prop.enum.map(v => <option key={v} value={v}>{v}</option>)}
            </select>
          ) : (
            <input type="text" value={params[key] || ''} onChange={e => setParams({...params, [key]: e.target.value})} placeholder={prop.description} />
          )}
        </div>
      ))}
      <button onClick={handleExecute} disabled={loading}>
        {loading ? 'מריץ...' : 'הפעל כלי'}
      </button>
      {execution && (
        <div className="execution-status">
          סטטוס: {execution.status} {execution.result && <pre>{JSON.stringify(execution.result, null, 2)}</pre>}
        </div>
      )}
    </div>
  );
}
```

### שלב 3: שילוב בלוח-המשימות
- הוספת כפתור `⚙️ הפעל כלי` בכותרת כל כרטיס משימה (ב-`TaskCard.tsx`)
- לחיצה פותחת `<ArsenalLauncher taskId={task.id} onExecutionComplete={handleResult} />` ב-Side Panel (כמו פרטי משימה)
- `handleResult` מעדכן את המשימה: מוסיף `executionLog` עם קישור לבלוק Ledger

## מדדי הצלחה
| מדד | יעד |
|------|------|
| זמן ממוצע: פתיחת משימה → הרצת כלי ראשונה | < 30 שניות |
| % משימות עם לפחות הפעלת כלי אחת | > 60% תוך חודש |
| שגיאות פרמטרים (validation errors) | < 5% מההרצות |
| בלוקי Ledger חדשים מסוג `tool_execution` | > 50/שבוע |

## סיכונים ותגובות
| סיכון | תגובה |
|--------|--------|
| כלי עם הרצה ארוכה (>5 דק') | polling עם WebSocket עתידי; כרגע — ספינר + הודעה "רץ ברקע" |
| פרמטרים רגישים (סיסמאות, מפתחות) | שדה `secret: true` ב-schema → הצפנה בצד-לקוח לפני שליחה; לא נשמר ב-Ledger |
| כלי שנכשל חלקית | תוצאה מכילה `partial: true` + פירוט; המשימה נשארת פתוחה |

**הערה**: הצעה זו לא דורשת שינוי סכמת מסד-נתונים, לא שוברת API קיים, וניתנת למימוש ב-2-3 ימי עבודה של מפתח אחד. היא הופכת את ה-Arsenal מ-"ספריית כלים" ל-"זרוע ביצוע" של לוח-המשימות — בדיוק מה שהריבונות צריכה.
