# ממשק CLI מאוחד להפעלת רכיבי הארסנל עם פרמטרים מובנים

## הצעה: ממשק CLI מאוחד לרכיבי הארסנל

### הבעיה
כרגע כל כלי בארסנל מופעל בנפרד עם ממשק שונה, פרמטרים לא עקביים, ואין דרך סטנדרטית לשרשר כלים או לטפל בשגיאות בצורה אחידה. זה מקשה על אוטומציה, בדיקות, ושימוש חוזר.

### הפתרון המוצע
ממשק CLI יחיד (`saos-tool`) שמהווה נקודת כניסה לכל רכיבי הארסנל:

```bash
# הפעלה בסיסית
saos-tool <component> [args...]

# דוגמאות
saos-tool vault-rotate --secret SOVEREIGN_VAULT_SECRET --dry-run
saos-tool edge-verify --runtime nodejs --libs auth,db
saos-tool chain-audit --from-block 1800 --to-block 1819

# שרשור עם pipe
saos-tool vault-rotate --secret X --output json | saos-tool chain-audit --input stdin

# מצב batch
saos-tool batch --file workflow.yaml
```

### מבנה טכני
1. **Entry point יחיד** - `packages/cli/src/index.ts` עם Commander.js
2. **רישום רכיבים דינמי** - כל כלי מייצא `defineTool({ name, schema, execute })`
3. **סכימת פרמטרים** - Zod schemas לוולידציה אוטומטית והצגת עזרה
4. **טיפול שגיאות אחיד** - קודי יציאה סטנדרטיים, JSON error output
5. **לוגינג מובנה** - רמות (debug/info/warn/error), פורמט JSON/pretty
6. **תמיכת stdin/stdout** - לשרשור כלים ב-pipes

### יתרונות
- **עקביות**: אותו ממשק לכל הכלים
- **אוטומציה**: קל לכתוב סקריפטים ו-workflows
- **בדיקות**: אפשר להריץ כלים ב-CI עם פרמטרים מדויקים
- **ניפוי**: `--verbose` ו-`--dry-run` בכל כלי אוטומטית
- **תיעוד עצמי**: `saos-tool --help` ו-`saos-tool <component> --help`

### תוכנית מימוש
1. יצירת חבילת `packages/cli` עם Commander + Zod
2. הגדרת ממשק `ToolDefinition` משותף
3. העברת כלי קיים אחד (למשל `vault-rotate`) לממשק החדש
4. הוספת סקריפט `saos-tool` ל-package.json root
5. תיעוד ב-README עם דוגמאות

### מדדי הצלחה
- כל כלי קיים עובד דרך `saos-tool <name>`
- זמן הוספת כלי חדש < 10 דקות
- כיסוי בדיקות CLI > 80%
- תיעוד מלא לכל פרמטר
