# מדריך תפעול: שער ההעברה לגיט (Git Handoff Gate)

שער ההעברה הוא **נקודת הבקרה הריבונית** — שום קוד לא נפרס בלי אישור בעלים. המדריך מכסה את הזרימה המלאה: מקבלת התראה ועד סגירת המעגל.

---

## 1. איפה רואים את התור
- **קיר הצמיחה (Improvements Wall)** — כרטיסי "הצעת העברה ממתינה" עם מונה שעות דביק.
- **API ישיר**: `GET /api/handoffs?status=pending` — מחזיר מערך אובייקטים:
  ```json
  [
    {
      "id": "cmvfxj6g",
      "repo": "saos-dex",
      "path": "fabric/cmvfxj6g/lodash-saos-dex.ts",
      "submittedAt": "2026-10-20T00:12:00Z",
      "hoursWaiting": 13,
      "author": "worker-7",
      "summary": "הוספת wrapper ל-lodash עם טיפוסים מותאמים ל-SAOS"
    }
  ]
  ```

## 2. בדיקה מהירה (2–3 דקות)
| שלב | פעולה | כלי/פקודה |
|-----|--------|------------|
| 2.1 | פתח את הקובץ בגיטהאב/גיטלאב | קישור ישיר מה-API: `https://github.com/<org>/<repo>/blob/main/<path>` |
| 2.2 | הרץ בדיקות מקומיות (אם רלוונטי) | `npm test -- --testPathPattern=<path>` |
| 2.3 | ודא שאין סודות/מפתחות בקוד | חיפוש `api_key`, `secret`, `password` |
| 2.4 | בדוק התאמה לסטנדרטים (ESLint, Prettier, טיפוסים) | `npx eslint <path> && npx prettier --check <path>` |

> **כלל אצבע**: אם הקוד עובר CI ירוק + אין דגלים אדומים בבדיקה ידנית → **אשר**. אחרת → **דחה עם משוב קונקרטי**.

## 3. החלטה וביצוע
### אישור
```bash
curl -X POST https://<domain>/api/handoffs/cmvfxj6g/approve \
  -H "Authorization: Bearer $OWNER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"note": "נקי, עובר CI, תואם סטנדרטים"}'
```
- התגובה: `{ "status": "approved", "deployTriggered": true }`
- הפריסה מתחילה אוטומטית; עקוב אחריה ב-`/api/metrics?filter=deployment`.

### דחייה
```bash
curl -X POST https://<domain>/api/handoffs/cmvfxj6g/reject \
  -H "Authorization: Bearer $OWNER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"reason": "חסר טיפוס לפונקציה export ברורה 42", "suggestedFix": "הוסף `export function foo(): Bar { ... }`"}'
```
- העובד מקבל התראה מיידית עם המשוב; הכרטיס חוזר ל-"בבדיקה".

## 4. מעקב אחרי פריסה (אחרי אישור)
1. פתח `GET /api/metrics?event=deployment&handoffId=cmvfxj6g` — מחכה ל-`status: "success"`.
2. אם `status: "failed"` — פתח לוגים: `GET /api/handoffs/cmvfxj6g/logs`.
3. על כישלון: החלט — **תיקון חוזר** (העובד מתקן ומגיש מחדש) או **ביטול** (סגירת הכרטיס).

## 5. ניקוי תור ישן (שגרתי, פעם ביום)
- סנן `hoursWaiting > 24` — אלו תקועים.
- לכל אחד: שלח תזכורת לעובד (`POST /api/handoffs/<id>/nudge`) או דחה אם לא רלוונטי.
- רשום ביומן: `echo "$(date) cleaned <id>" >> ~/handoff-gate.log`.

## 6. צ'ק-ליסט יומי (הדפס/הצמד למסך)
- [ ] פתח תור ממתינים (`/api/handoffs?status=pending`)
- [ ] עבור כל כרטיס: בדיקה מהירה → החלטה → ביצוע
- [ ] ודא שאין כרטיסים > 24 שעות בלי פעולה
- [ ] עדכן לוג ניקוי
