# מדד-הצטברות-למידה-רשתית לפי משמרת

## למה זה חשוב?
הרשת לומדת כל הזמן — אבל לא כל למידה שווה. יש משמרות שבהן הלמידה עמוקה ומקובעת, ואחרות שבהן היא שטחית או נעלמת. מדד זה מודד את **הידע שנשמר** (לא רק מיוצר) ברשת לאורך זמן, לפי משמרת, כדי להבין מתי הרשת קולטת בצורה יעילה — ולהתאים את עומס המשימות והאתגרים לפי יכולת הקליטה האמיתית שלה.

## איך זה עובד?
כל למידה שמיוצרת ברשת (דרך `/api/evolution`) נבדקת אם היא:
- נשמרה ב-`learned` (לא נמחקה או נדחתה)
- עדיין זמינה אחרי 24 שעות (לא נמחקה עקב סתירה או חוסר רלוונטיות)
- קיבלה לפחות אישור אחד מ-Worker אחר (אישור-ריבוני)

המדד מחשב:
```json
{
  "shift": "לילה" | "בוקר" | "ערב",
  "date": "YYYY-MM-DD",
  "learnedRetained": number,   // כמות הידע שנלמד ונשמר במשמרת
  "produced": number,           // כמות הידע שנוצר (ללא בדיקת שמירה)
  "retentionRate": number,      // אחוז השימור: learnedRetained / produced
  "openLoops": number,          // כמה למידות פתוחות עדיין ממתינות לאישור או בדיקה
  "networkHealthScore": number  // ציון בריאות כללי: (learnedRetained * 0.4) + (retentionRate * 30) - (openLoops * 0.5)
}
```

הנתונים נאספים אוטומטית מהשרשרת ומהמטא-דאטה של `/api/evolution` ו-`/api/metrics`, ומעודכנים כל שעה.

## איך להציג את זה?
בפאנל חדש בלוח-המשימות: **"מדד הלמידה השמורה"**
- גרף עמודות יומי: כל משמרת (בוקר/ערב/לילה) כעמודה, גובה = `learnedRetained`
- קו עליון: `retentionRate` באחוזים (0–100%)
- צבעי רקע לפי `networkHealthScore`: ירוק (>70), צהוב (40–70), אדום (<40)
- כפתור "למה זה נמוך?" שפותח פירוט: אילו למידות נדחו, למה, ומי היה מעורב.

## ערך מוסף
- מאפשר לזהות אם משמרת הלילה באמת "עורקי-הלב" — או רק שם שווא.
- עוזר למנוע עומס יתר בלמידה: אם שימור נמוך, מפחיתים משימות חדשות ומגדילים חזרה ולימוד.
- יוצר משוב אמיתי על איכות הלמידה — לא רק כמות.
- מחזק את העיקרון: רשת חיה לא מודדת כמה היא מייצרת — אלא כמה היא **שומרת**.
