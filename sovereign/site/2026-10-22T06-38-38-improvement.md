# מדריך ניהול סודות בסביבת ריבונות אוטונומית

> **מטרה**: לספק תבנית מעשית, ניתנת-לביקורת ומתאימה-להרחבה לניהול סודות במערכת שבה רכיבים לומדים, מתקשרים ומתפתחים עצמאית.

---

## 1. עקרונות יסוד

| # | עיקרון | תיאור קצר | בדיקת-קבלה (Definition of Done) |
|---|---------|------------|-----------------------------------|
| 1 | **אפס-אמון בקוד** | סודות לעולם לא נכתבים בקוד, בקבצי הגדרות בגיט, או בלוגים | סריקת `git log --all --full-history -- "*.env" "*.json" "*.yaml"` מחזירה 0 תוצאות עם ערכים חשודים |
| 2 | **הזרקה בזמן-הרצה בלבד** | סודות מוזרקים דרך משתני-סביבה או מנהל-סודות חיצוני (Vault, AWS Secrets Manager, 1Password CLI) | כל שירות עולה עם `env | grep -E "KEY|SECRET|TOKEN"` — רק משתנים, לא ערכים |
| 3 | **סיבוב אוטומטי** | לכל סוד יש TTL מוגדר ותהליך סיבוב אוטומטי (cron / operator) | דוח סיבוב חודשי מופק אוטומטית; אין סוד בן > 90 יום |
| 4 | **הרשאה מינימלית (Least Privilege)** | כל רכיב מקבל גישה רק לסודות שהוא צריך, בזמן שהוא צריך | מדיניות IAM/RBAC נבדקת ב-CI עם `opa eval` או `kyverno` |
| 5 | **ביקורת שרשרת-אמת** | כל גישה לסוד נרשמת ב-ledger עם hash-chain לאי-הכחשה | שאילתת ledger: `SELECT * FROM ledger WHERE action='secret_access' AND ts > now() - interval '24h'` מחזירה רשומות תקינות |
| 6 | **הפרדת סביבות** | סודות dev/staging/prod מופרדים פיזית/לוגית; אין זליגה | `namespace`/`project` נפרדים במנהל-הסודות; בדיקת זליגה אוטומטית ב-CI |
| 7 | **הצפנה במנוחה ובתנועה** | אחסון מוצפן (AES-256-GCM), תקשורת TLS 1.3 בלבד | סריקת `nmap --script ssl-enum-ciphers` על פורטי מנהל-הסודות — רק TLS 1.3 |
| 8 | **ניהול מחזור-חיים מלא** | יצירה → הפצה → שימוש → סיבוב → ביטול — כל שלב מתועד וניתן-לביקורת | דיאגרמת מצב (state machine) בקוד; מעבר מצב לא-מורשה נכשל ב-unit test |
| 9 | **זיהוי דליפה אוטומטי** | סריקת קוד, לוגים, artifacts, container images לאיתור סודות | `trufflehog` / `gitleaks` / `syft` ב-pipeline; כישלון = build אדום |
| 10 | **תגובת-אירוע מוכנה** | נוהל ביטול-מיידי והחלפה של סוד שדלף, כולל תקשורת לבעלי-עניין | Runbook מתועד; תרגיל רבעוני עם מדידת MTTR |
| 11 | **סודות זמניים למשימות קצרות** | למשימות batch/CI — שימוש ב-Short-lived tokens (OIDC, JWT, AWS STS) במקום מפתחות קבועים | אין `AWS_ACCESS_KEY_ID` ב-CI; רק `oidc-token` עם TTL ≤ 1h |
| 12 | **תיעוד חי ונגיש** | מסמך זה מתעדכן בכל שינוי ארכיטקטורה; גרסה ב-git עם חתימת ledger | `git log -1 --format="%H %s" -- docs/secrets-management.md` תואם hash ב-ledger |

## 2. תבניות יישום (Patterns)

### 2.1 תבנית: Sidecar Secret Injector
```yaml
# k8s deployment snippet
containers:
  - name: app
    image: my-app:latest
    envFrom:
      - secretRef:
          name: app-secrets  # מנוהל חיצונית, מסונכרן ע"י operator
  - name: vault-agent
    image: hashicorp/vault-agent:latest
    volumeMounts:
      - name: vault-token
        mountPath: /var/run/secrets/vault
    env:
      - name: VAULT_ADDR
        value: "https://vault.internal"
```

### 2.2 תבנית: CI/CD OIDC Token Exchange (GitHub Actions → AWS/GCP/Azure)
```yaml
# .github/workflows/deploy.yml
permissions:
  id-token: write
  contents: read
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::123456789:role/GitHubActionsDeploy
          aws-region: us-east-1
      - run: ./deploy.sh  # הסקריפט מקבל credentials זמניים אוטומטית
```

### 2.3 תבנית: Application-Level Secret Cache with TTL
```python
# Python example — cache עם רענון אוטומטי
import os, time, threading
from functools import lru_cache

class SecretCache:
    def __init__(self, ttl_seconds=300):
        self._cache = {}
        self._ttl = ttl_seconds
        self._lock = threading.Lock()
    
    def get(self, key: str) -> str:
        with self._lock:
            now = time.time()
            if key in self._cache:
                value, expiry = self._cache[key]
                if now < expiry:
                    return value
            # fetch from env / vault / file
            value = os.environ[key]  # או קריאה ל-Vault API
            self._cache[key] = (value, now + self._ttl)
            return value

secrets = SecretCache(ttl_seconds=300)
DB_PASSWORD = secrets.get("DB_PASSWORD")
```

## 3. רשימת בדיקה (Checklist) לשילוב ב-Definition of Done של כל PR

- [ ] אין ערכי סוד בקוד החדש (לא hardcoded, לא ב-comments, לא ב-test fixtures)
- [ ] משתני סביבה חדשים מתועדים ב-`.env.example` עם ערכי-דמה
- [ ] סודות חדשים נוספו למנהל-הסודות המרכזי עם תגיות: `owner`, `ttl`, `environment`, `rotation-schedule`
- [ ] מדיניות גישה עודכנה ונבדקה ב-CI (`opa test policies/secrets/...`)
- [ ] לוגי גישה לסודות החדשים מופיעים ב-ledger (הרצת בדיקה ידנית + שאילתה)
- [ ] סריקת `gitleaks`/`trufflehog` עוברת ב-pipeline
- [ ] אם נוסף סוד חדש ל-CI — משתמש ב-OIDC/Short-lived token בלבד
- [ ] Runbook תגובת-אירוע עודכן אם נוסף סוג סוד חדש

## 4. מדדים למעקב (KPIs)

| מדד | יעד | מקור נתונים |
|------|------|--------------|
| גיל סוד מקסימלי (ימים) | ≤ 90 | Vault API / AWS Secrets Manager API |
| זמן ממוצע לסיבוב (MTTR סיבוב) | ≤ 2 שעות | Runbook timestamps |
| מספר דליפות שזוהו אוטומטית בחודש | 0 | CI pipeline reports |
| אחוז שירותים עם sidecar injector | 100% | k8s inventory script |
| כיסוי מדיניות OPA/RBAC | 100% | `opa eval` coverage report |

## 5. התאמה לשרשרת-אמת וללמידה עצמית

- **כל שינוי במדיניות סודות** → נרשם כ-tranaction ב-ledger עם `kind: "secret_policy_change"`
- **ממצא HIGH מסריקת דליפה** → פותח task אוטומטי ב-Dispatch עם `severity: "critical"`, `tags: ["secret-leak", "auto-generated"]`
- **סיבוב סוד מוצלח** → מייצר `memory` entry עם `learned: true`, `tags: ["secret-rotation", "success"]`
- **כישלון סיבוב** → מייצר `HIGH` finding עם פרטי כישלון + קישור ל-runbook הרלוונטי
