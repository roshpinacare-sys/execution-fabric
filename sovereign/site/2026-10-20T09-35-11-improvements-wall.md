# מדריך תפעול: קיר הצמיחה (Improvements Wall)

> **משטח**: `קיר-הצמיחה (Improvements)`  
> **קהל**: מנהלי מוצר, מובילי צוות, סוקרים, וכל מי שמקדם שיפורים מהצעה למסירה  
> **מטרה**: לאפשר זרימה חלקה — **הצעה → דיון → החלטה → ביצוע → מדידה → סגירה** — בלי איבוד הקשר.

---

## 1. פתיחה וניווט בסיסי

| פעולה | איך מבצעים | קיצור מקלדת | הערה |
|--------|-------------|---------------|-------|
| פתיחת הקיר | תפריט צד → **קיר הצמיחה** / כתובת `/improvements` | `g` → `i` | נטען אוטומטית עם 50 פריטים אחרונים |
| רענון ידני | כפתור ⟳ בפינה עליונה-שמאלית | `r` | שומר מיקום גלילה וסינון |
| מעבר למצב מסך מלא | לחיצה על ⛶ בכותרת הקיר | `f` | מסתיר סרגל צד |

**מבנה המסך** (מימין לשמאל):
1. **סרגל סינון** — טקסט חופשי, סוג, סטטוס, בעלים, טווח תאריכים
2. **רשימת כרטיסים** — כרטיס לכל שיפור (ראו סעיף 2)
3. **פאנל פרטים** — נפתח בלחיצה על כרטיס (ראו סעיף 3)

---

## 2. כרטיס שיפור — קריאה מהירה

כל כרטיס מציג:
```
[סוג] כותרת ייחודית                    #1234  ● סטטוס
  תגיות: #frontend #accessibility #rtl   בעלים: @user  עודכן: 2026-10-19
  ────────────────────────────────────────
  סיכום: שורה תמציתית אחת
  השפעה מוערכת: ★★★☆☆  מאמץ: ★★☆☆☆
```

### קודי צבע סטטוס
| סטטוס | צבע | משמעות | פעולה הבאה טיפוסית |
|-------|------|---------|---------------------|
| `PROPOSED` | 🟦 כחול | הוצע, טרם נדון | `Review` → `ACCEPTED`/`REJECTED` |
| `ACCEPTED` | 🟩 ירוק | אושר לביצוע | הקצאה → `IN_PROGRESS` |
| `IN_PROGRESS` | 🟨 צהוב | בביצוע פעיל | עדכון התקדמות → `READY_FOR_REVIEW` |
| `READY_FOR_REVIEW` | 🟧 כתום | ממתין לסקירה/בדיקה | סקירה → `DELIVERED`/`NEEDS_WORK` |
| `DELIVERED` | 🟪 סגול | נמסר לייצור | מדידת השפעה → `ARCHIVED` |
| `ARCHIVED` | ⬜ אפור | סגור, נשמר להיסטוריה | — |
| `REJECTED` | 🟥 אדום | נדחה עם נימוק | יכול לחזור כ-`PROPOSED` חדש |

### פעולות מהירות על כרטיס (רחוף → אייקונים)
| אייקון | פעולה | הרשאה נדרשת |
|--------|--------|----------------|
| ✏️ | עריכת כותרת/סיכום/תגיות | בעלים / מנהל |
| 👤 | החלפת בעלים | מנהל |
| ➡️ | קידום סטטוס (לבא בתור) | בעלים / סוקר |
| 💬 | פתיחת דיון מובנה | כולם |
| 📎 | צירוף קובץ/קישור PR/לוג | בעלים |
| 🗑️ | ארכוב / דחייה | מנהל |

## 3. פאנל פרטים — עומק מלא

לחיצה על כרטיס פותחת פאנל צידי עם לשוניות:

### 📋 סקירה כללית
- **מזהה ייחודי** (UUID + מספר סידורי)
- **היסטוריית סטטוס** — ציר זמן עם חותמות זמן ומבצע
- **קישורים קשורים** — PRs, Issues, מסמכי עיצוב, הקלטות
- **מדדי השפעה** (מתעדכנים אוטומטית אחרי `DELIVERED`):
  - זמן מחזור (Cycle Time): הצעה → מסירה
  - זמן הובלה (Lead Time): התחלת עבודה → מסירה
  - שינוי במדדי מוצר רלוונטיים (לפני/אחרי)

### 💬 דיון מובנה
- שרשור תגובות עם @אזכורים
- **החלטות מתועדות** — כפתור "קבע החלטה" מוסיף חותמת: `✅ הוחלט: ...`
- סימון "נפתר" על תגובות ספציפיות

### 📊 מדידה והשפעה
| מדד | מקור | תדירות עדכון |
|------|-------|-----------------|
| אימוץ פיצ'ר | Analytics events | יומי |
| שגיאות/ביצועים | Sentry / Metrics API | זמן אמת |
| משוב משתמשים | In-app feedback | שבועי |
| חיסכון בזמן/עלות | הערכת צוות | חד-פעמי בסגירה |

> **טיפ**: לחצן **"צור דוח השפעה"** מייצר Markdown מוכן לשיתוף בדוח שבועי.

## 4. זרימות עבודה נפוצות

### 4.1 מהצעה לקבלה (Proposed → Accepted)
1. **סוקר** פותח כרטיס `PROPOSED`
2. קורא סיכום, בודק תגיות, מעריך השפעה/מאמץ
3. מוסיף תגובה: `👍 מקבל — מקצה ל-@dev` או `❓ צריך הבהרה: ...`
4. לוחץ **➡️ קידום** → `ACCEPTED`
5. מערכת שולחת התראה לבעלים החדש

### 4.2 ביצוע ומסירה (Accepted → Delivered)
1. **בעלים** מעביר ל-`IN_PROGRESS` בתחילת עבודה
2. מעדכן התקדמות בתגובות (לפחות פעם ביום)
3. בסיום: מצרף קישור PR, לוחץ ➡️ → `READY_FOR_REVIEW`
4. **סוקר** בודק, מאשר → `DELIVERED`
5. **אוטומציה**: מדדי השפעה מתחילים להיאסף

### 4.3 סגירה ולמידה (Delivered → Archived)
1. לאחר **14 יום** ב-`DELIVERED` (ברירת מחדל, ניתן לשינוי)
2. בעלים/מנהל לוחץ **"צור דוח השפעה"**
3. אם מדדים עומדים ביעד → ➡️ `ARCHIVED`
4. אם לא → דיון → החלטה: `EXTEND_MEASUREMENT` / `ROLLBACK` / `ITERATE`

## 5. סינון, חיפוש ותצוגות שמורות

### מסננים מהירים (כפתורים מעל הרשימה)
| כפתור | שאילתה |
|--------|----------|
| 🔥 שלי | `owner:@me status:!ARCHIVED,!REJECTED` |
| ⏳ ממתינים לי | `reviewer:@me status:READY_FOR_REVIEW` |
| 🚀 בביצוע | `status:IN_PROGRESS` |
| 📈 למדידה | `status:DELIVERED age:<14d` |
| 🗂️ ארכיון | `status:ARCHIVED` |

### חיפוש טקסט חופשי
- מחפש בכותרת, סיכום, תגיות, גוף, מזהה
- אופרטורים: `title:"כפתור"`, `tag:accessibility`, `status:PROPOSED`, `owner:@user`

### תצוגות שמורות (Saved Views)
1. כוונן מסננים → לחץ 💾 "שמור תצוגה"
2. תן שם (למשל: "אקססיביליטי Q4")
3. נגיש בתפריט 📋 "תצוגות שלי" — מסתנכרן בין מכשירים

## 6. אינטגרציות ואוטומציה

| טריגר | פעולה אוטומטית | הגדרה |
|--------|----------------|--------|
| PR נפתח עם `improves:#123` | כרטיס → `IN_PROGRESS`, קישור PR נוסף | הגדרות → אינטגרציות → Git |
| PR מוזג | כרטיס → `READY_FOR_REVIEW` | אותו מקום |
| Deploy ל-production | כרטיס `DELIVERED` מקבל חותמת deploy | Webhook `/api/improvements/deploy` |
| 7 ימים בלי פעילות | תזכורת אוטומטית לבעלים/סוקר | הגדרות → התראות |
| מדד השפעה חורג סף | התראה בערוץ #improvements-alerts | הגדרות → מדדים |

**API מפתח** (לסקריפטים חיצוניים):
```bash
# רשימת כרטיסים פתוחים
curl -H "Authorization: Bearer $TOKEN" \
  "https://api.product/improvements?status=PROPOSED,ACCEPTED,IN_PROGRESS"

# עדכון סטטוס
curl -X PATCH -H "Authorization: Bearer $TOKEN" \
  -d '{"status":"ACCEPTED"}' \
  "https://api.product/improvements/uuid-1234"
```

## 7. רשימת ביקורת (Checklist) לסוקר שבועי

> פתח תצוגה "⏳ ממתינים לי" בכל יום שני — עבר על כל כרטיס:

- [ ] **PROPOSED** — האם ברור? האם יש הערכת השפעה/מאמץ? → קבל/דחה/בקש הבהרה
- [ ] **READY_FOR_REVIEW** — האם PR נבדק? האם מדדים מוגדרים? → אשר/החזר
- [ ] **DELIVERED > 14 יום** — האם יש דוח השפעה? → ארכב/הארך/איטרציה
- [ ] **IN_PROGRESS > 7 ימים בלי עדכון** → תזכר בעלים
- [ ] **REJECTED עם תגובות חדשות** → הערך מחדש

## 8. טיפים מתקדמים

1. **תגיות סטנדרטיות** — השתמש במילון המשותף: `#frontend` `#backend` `#infra` `#ux` `#a11y` `#perf` `#security` `#docs` `#tooling` — מאפשר דוחות חתך.
2. **פיצול שיפורים גדולים** — אם מאמץ > ★★★★☆, צור כרטיסי-בן עם `parent:#1234` — הקיר מציג עץ התקדמות.
3. **קישור למשימות Dispatch** — הוסף `dispatch:#task-id` בתגיות — הקיר מראה סטטוס משימה מקושרת.
4. **מצב "מיקוד"** — לחץ `z` — מסתיר הכל חוץ מכרטיסים שאתה בעלים/סוקר שלהם.
5. **ייצוא ל-CSV/Markdown** — תפריט ⋮ → "ייצא תצוגה נוכחית" — לדוחות הנהלה.

## 9. פתרון בעיות נפוצות

| תסמין | סיבה סבירה | פתרון |
|--------|--------------|--------|
| כרטיס לא מופיע בסינון | סטטוס/בעלים לא תואם | בדוק ערכים מדויקים (case-sensitive) |
| מדדי השפעה ריקים אחרי DELIVERED | אירועי analytics לא מוגדרים | ודא `improvementId` נשלח באירועים |
| התראות לא מגיעות | ערוץ Slack/Email לא מחובר | הגדרות → התראות → בדוק חיבור |
| קידום סטטוס נכשל | חסר הרשאה / שדה חובה | הודעת שגיאה בתחתית הפאנל |
| כרטיס "תקוע" ב-IN_PROGRESS | בעלים לא פעיל / חסימה לא מדווחת | העבר בעלות / הוסף תגית `#blocked` |

## 10. שאלות נפוצות (FAQ)

**ש: איך מוחקים כרטיס לצמיתות?**
ת: לא מוחקים — רק `ARCHIVED` או `REJECTED`. מחיקה שוברת שרשרת אמת ולמידה.

**ש: האם אפשר לשנות סוג (CONTENT/DATA/PROPOSAL) אחרי יצירה?**
ת: כן — עריכה ✏️ → שדה "סוג". משנה רק תצוגה ודוחות, לא היסטוריה.

**ש: איך מגדירים יעד השפעה מותאם?**
ת: בפאנל פרטים → לשונית מדידה → "הגדר יעד" → בוחר מדד, סף, תאריך יעד.

**ש: האם הקיר תומך ב-RTL מלא?**
ת: כן — כל הממשק RTL נייטיבי, כולל טבלאות, טפסים, תאריכים עבריים.
