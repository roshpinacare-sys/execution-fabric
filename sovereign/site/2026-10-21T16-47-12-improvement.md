# מדריך פתרון תקלות נפוצות בממשק הפיקוח

## סקירה כללית
מדריך זה מסייע למשתמשים לזהות, לאבחן ולטפל בתקלות תקינות נתונים נפוצות המתרחשות במערכת, עם דגש על לוח המשימות ומדדי הרשת. המדריך מספק תהליכים מעשיים ובדיקות כדי לאבטח את תקינות המידע ולשפר את האמינות של הנתונים המוצגים.

## תקלות נפוצות ופתרונות

### 1. אי-התאמה בין מספרי משימות
**תיאור התקלה:** המספר המוצג בלוח המשימות אינו תואם את המספר הצפוי מהמערכת.

**בדיקות לביצוע:**
- הפעלת שאילתה ידנית ל-API `/api/metrics` לקבלת נתונים עדכניים
- בדיקת התאמה בין הנתונים המוצגים בממשק לבין הנתונים הגולמיים
- רענון הממשק וצפייה אם הבעיה חוזרת

**פתרון:**
```javascript
// דוגמת קוד לסנכרון נתונים
const syncMetrics = async () => {
  try {
    const response = await fetch('/api/metrics');
    const data = await response.json();
    updateDashboard(data);
  } catch (error) {
    console.error('שגיאה בסנכרון נתונים:', error);
  }
};
```

### 2. ערכים חסרים במדדי הרשת
**תיאור התקלה:** חלק מהמדדים בממשק מוצגים כריקים או כ-NaN.

**בדיקות לביצוע:**
- בדיקת קישור ה-API למקור הנתונים
- הפעלת בדיקת תקינות ה-JSON המתקבל
- וידוא שה-API מחזיר נתונים בפורמט הצפוי

**פתרון:**
```javascript
// דוגמת קוד לטיפול בערכים חסרים
const sanitizeMetrics = (metrics) => {
  return metrics.map(metric => ({
    ...metric,
    value: metric.value || 0,
    timestamp: metric.timestamp || new Date().toISOString()
  }));
};
```

### 3. עיכוב בעדכון זמני הפעלת תהליכים
**תיאור התקלה:** זמני ההפעלה המוצגים בלוח המשימות אינם מעודכנים.

**בדיקות לביצוע:**
- השוואת זמני ההפעלה בין מערכת התזמון לבין הממשק
- בדיקת תקינות שרשרת האירועים (Event Log)
- וידוא שהמערכת מקבלת את הזמנים מהמקור הנכון

**פתרון:**
```javascript
// דוגמת קוד לסנכרון זמני הפעלה
const syncExecutionTimes = async () => {
  const response = await fetch('/api/metrics/execution-times');
  const executionTimes = await response.json();
  updateExecutionTimes(executionTimes);
  scheduleNextSync();
};
```

## טיפים למניעת תקלות

1. **רענון קבוע:** הפעל רענון ידני של הממשק כל 5 דקות כדי לוודא שהנתונים עדכניים.

2. **בדיקות תקינות:** בצע בדיקות תקינות של ה-API לפני כל שימוש בנתונים.

3. **דיווח תקלות:** במקרה של תקלה, דווח עליה במערכת הדיווח עם פרטים מלאים על התנאים שבהם התרחשה.

4. **ניטור:** הפעל ניטור רציף של מדדי הרשת כדי לזהות מוקדם סטיות מהנורמה.
