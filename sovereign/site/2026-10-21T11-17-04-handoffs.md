# מדריך תפעול: ניהול הצעות העברה (Handoffs) — זרימת אישור, בדיקה ופריסה בטוחה

# מדריך תפעול: ניהול הצעות העברה (Handoffs)

> **מטרה**: לאפשר לריבון לטפל בהצעות העברה ממתינות בביטחון, במהירות ובאפס הפתעות.

---

## 1. זיהוי הצעות ממתינות

| פעולה | כלי / פקודה | תדירות |
|--------|--------------|----------|
| הצגת כל ההצעות הפתוחות | `GET /api/handoffs?status=pending` | בכל פתיחת משמרת |
| סינון לפי גיל (שעות) | `?status=pending&olderThan=4` | יומי |
| התראות על הצעות > 6 שעות | Webhook / קונסולת התראות | אוטומטי |

**סימני אזהרה**:
- הצעה שממתינה > 6 שעות (כרגע 3 הצעות כאלו)
- הצעה ממאגר לא מוכר או נתיב חריג
- מספר הצעות מאותו מאגר בו-זמנית

---

## 2. בדיקה מקדימה (Pre-flight) — לפני אישור

```bash
# 1. משיכת הקוד המוצע
curl -H "Authorization: Bearer $TOKEN" \
  "https://api.product/handoffs/{id}/diff" > proposed.patch

# 2. הרצת בדיקות מקומיות (אם רלוונטי)
cd /workspace/repo
patch -p1 < proposed.patch
npm ci && npm test && npm run lint

# 3. בדיקת שרשרת-אמת — האם ה-hash-chain תקין?
node scripts/verify-chain.js --since-last-good
```

**צ'ק-ליסט מהיר**:
- [ ] ה-diff קריא וממוקד (לא "הכל בבת אחת")
- [ ] הבדיקות עוברות מקומית
- [ ] אין שבירת API ציבורי ללא גרסה
- [ ] הלוגר/מטריקות מעודכנים בשינוי
- [ ] תיעוד קצר מצורף (או קישור ל-PR)

---

## 3. החלטה: אישור / דחייה / בקשת תיקון

| החלטה | פעולה בקונסולה | תוצאה |
|--------|------------------|--------|
| **אישור** | `POST /api/handoffs/{id}/approve` | פריסה אוטומטית לסביבת יעד |
| **דחייה** | `POST /api/handoffs/{id}/reject` + סיבה | חוזר למציע עם הערות |
| **תיקון נדרש** | `POST /api/handoffs/{id}/request-changes` + פירוט | מצב `changes_requested` |

**עקרון**: *אף פריסה בלי אישור בעלים* — השער ממתין לריבוני.

---

## 4. מעקב אחרי פריסה מאושרת

1. **וידוא בריאות מיידי** (2 דקות ראשונות):
   - `GET /api/metrics?window=5m` — שגיאות, latency, throughput
   - `GET /api/chain/status` — גובה שרשרת, כשלים חדשים

2. **אישור סופי** (אחרי 10 דקות יציבות):
   - סימון ההצעה כ-`delivered` בקונסולה
   - עדכון לוג הפריסות הפנימי

3. **Rollback מהיר** (אם נדרש):
   - `POST /api/handoffs/{id}/rollback` — חוזר לגרסה קודמת תקינה
   - דיווח אוטומטי למציע עם סיבת הכשל

---

## 5. שגרה יומית מומלצת

| זמן | פעולה |
|------|--------|
| 08:30 | סריקת הצעות פתוחות + סיווג לפי דחיפות |
| 09:00 | בדיקת Pre-flight להצעות > 4 שעות |
| 11:00 | החלטות על הצעות שהבשילו |
| 15:00 | מעקב פריסות בוקר + Rollback אם צריך |
| 17:00 | ניקוי הצעות ישנות (> 24 שעות) — דחייה או הסלמה |

## 6. תבנית תגובה מהירה (להעתקה)

```markdown
## החלטה: [אישור / דחייה / תיקון נדרש]
**הצעה**: `{id}` — `{repo/path}`
**סיבה**: 
- [ ] בדיקות עברו
- [ ] diff ממוקד
- [ ] אין שבירת חוזה
- [ ] תיעוד קיים
**הערות**: _______________
**חותם זמן**: `date -u +%Y-%m-%dT%H:%M:%SZ`
```

---

## 7. מדדי הצלחה לניהול Handoffs

| מדד | יעד |
|------|-----|
| זמן חציוני מקבלה להחלטה | < 4 שעות |
| אחוז פריסות מוצלחות (ללא rollback) | > 95% |
| הצעות שנדחו עקב diff לא ברור | < 10% |
| זמן ממוצע לזיהוי כשל פריסה | < 5 דקות |

---

> **טיפ זהב**: אם הצעה ממתינה > 6 שעות — היא כבר *סיכון תפעולי*. טפל בה עכשיו או הסלם.
