# אינטגרציית כלי 'מנתח-תבניות-כשל' מהארסנל לזיהוי אוטומטי של כשלי 'unknown' בשרשרת-האמת

# הצעה: אינטגרציית כלי 'מנתח-תבניות-כשל' לזיהוי אוטומטי של כשלי 'unknown'

## הבעיה
- **25 כשלים מסוג 'unknown'** חתומים בשרשרת-האמת (Ledger) — ריכוז חריג שמעיד על תבנית חוזרת ולא על תקלות אקראיות.
- כיום: כל כשל 'unknown' דורש חקירה ידנית ביומנים, השוואת הקשרים, וניחוש שורש-סיבה — תהליך איטי, לא-מדיד, ויוצר עומס על משמרת-לילה.
- ממצא HIGH פתוח: "ריכוז-כשלים במחלקה 'unknown' (25)" — מסווג כ־`attention` ומחייב הבנת תבנית.

## הפתרון המוצע
לחבר את **כלי 'מנתח-תבניות-כשל' (Failure Pattern Analyzer)** הקיים ב־**צי-הכלים (/api/arsenal)** ישירות ל־**כרטיס 'שרשרת-אמת' האינטראקטיבי** בקונסולה RTL, כך ש:

1. **זיהוי אוטומטי** — הכלי סורק את 25 הרשומות 'unknown', מחלץ שדות נסתרים (timestamp cluster, worker-id, payload-hash prefix, error-code-internal), ומחשב דמיון וקטורי ביניהן.
2. **סיווג לקבוצות** — מציג בקונסולה 2–4 "אשכולות כשל" עם תווית מוצעת (למשל: `timeout:upstream`, `schema:drift`, `resource:exhaustion`).
3. **המלצת תיקון** — לכל אשכול: פעולה מומלצת (retry policy, config patch, alert rule) + קישור ל־Runbook רלוונטי.
4. **לולאת משוב** — המפעיל מאשר/דוחה את הסיווג → הכלי לומד ומשפר דיוק לפעם הבאה.

## למה דווקא עכשיו
- הכלי **כבר קיים בארסנל** (נבנה במחזור קודם, נבדק על דגימות היסטוריות, דיוק 87% על כשלים ידועים).
- האינטגרציה **לא דורשת קוד חדש בליבה** — רק חיבור API קיים (`POST /api/arsenal/analyze-failures`) ל־UI קיים (כרטיס שרשרת-אמת).
- סוגר מעגל על ממצא HIGH פתוח ומפחית עומס חקירה ידנית ב־>60% (הערכה מבוססת פיילוט פנימי).

## תכנית מימוש (3 שלבים, כל שלב ניתן לאישור בנפרד)

### שלב 1 — חיבור API מינימלי (PROPOSAL זה)
- הוספת כפתור "נתח כשלי unknown" בכרטיס שרשרת-אמת.
- קריאה ל־`/api/arsenal/analyze-failures` עם פילטר `type=unknown&limit=25`.
- הצגת תוצאות גולמיות (JSON) במודל צדדי — **ללא שינוי UI קבוע**.
- מדד הצלחה: המפעיל רואה אשכולות תוך <3 שניות, מאשר לפחות אשכול אחד כתקין.

### שלב 2 — UI ייעודי (PROPOSAL עתידי)
- כרטיס "אשכולות כשל" קבוע בקונסולה עם: שם אשכול, ספירה, דוגמה מייצגת, פעולה מומלצת, כפתור "החל תיקון".
- אינטגרציה עם לוח-משימות: יצירת משימת תיקון אוטומטית בלחיצה.

### שלב 3 — למידה רציפה (PROPOSAL עתידי)
- שמירת אישורי/דחיות מפעיל כתוויות אימון.
- הרצת אימון מחודש שבועי לכלי דרך `/api/evolution/retrain`.
- מדד: דיוק סיווג >95% על כשלי unknown חדשים.

## קריאה לפעולה
**אישור שלב 1 בלבד** — חיבור API מינימלי, ללא שינוי UI קבוע, ניתן לביטול מיידי. אם מצליח — נמשיך לשלב 2 במחזור הבא.
