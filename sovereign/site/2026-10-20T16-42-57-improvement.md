# שאלות ותשובות: ניהול משימות תקועות בלוח הבקרה

## סקירה כללית
לוח המשימות (Dispatch → Workers) מציג משימות בסטטוסים שונים. משימה שנשארת ב-RUNNING מעל 30 דקות דורשת בדיקה — ייתכן שהיא תקועה, ממתינה למשאב חיצוני, או פשוט ארוכה מהצפוי.

---

## שאלות נפוצות

### ❓ איך מזהים משימה תקועה לעומת משימה ארוכה?
**סימנים למשימה תקועה:**
- סטטוס RUNNING מעל 30 דקות ללא עדכון התקדמות
- אין כתבי-לוג חדשים ב-5 דקות אחרונות
- שימוש CPU/זיכרון של ה-worker אפסי או קבוע

**סימנים למשימה ארוכה תקינה:**
- לוגים מתעדכנים בקביעות
- מדדי התקדמות (אחוזים, מונים) זזים
- שימוש משאבים תואם את אופי המשימה

### ❓ מה בודקים קודם כשמוצאים משימה תקועה?
1. **לוגי ה-worker** — חפש שגיאות, timeouts, או המתנה ל-lock
2. **תלות חיצונית** — API חיצוני, מסד נתונים, שירות קבצים
3. **מגבלות משאבים** — זיכרון, דיסק, חיבורי רשת
4. **קוד המשימה** — לולאות אינסופיות, retry ללא backoff

### ❓ איך משחררים משימה תקועה בבטחה?
```bash
# 1. סימון לחקירה (לא מוחק נתונים)
POST /api/tasks/{id}/flag-stuck

# 2. בקשת סיום רכה (SIGTERM ל-worker)
POST /api/tasks/{id}/graceful-stop

# 3. אם לא מגיב תוך 60 שניות — סיום כפוי
POST /api/tasks/{id}/force-stop
```

**אזהרה:** force-stop עלול להשאיר מצב לא עקבי. השתמש רק אחרי graceful-stop.

### ❓ איך מונעים הישנות?
- הגדר **timeout מקסימלי** לכל סוג משימה בקונפיגורציה
- הוסף **heartbeat** כל 30 שניות למשימות ארוכות
- הפעל **watchdog** שמזהה RUNNING מעל הסף ומתריע
- תעד **playbook** לכל סוג כשל חוזר

## טעויות נפוצות ותיקונן

| טעות | תיקון |
|-------|-------|
| מחכים "עוד קצת" בלי לבדוק לוגים | בדוק לוגים מיידית — 5 דקות חוסכות שעות |
| מפעילים force-stop בלי graceful-stop | תמיד נסה graceful-stop קודם |
| לא מתעדים את סיבת התקיעה | כתוב post-mortem קצר בלוח הצמיחה |
| מגדירים timeout אחיד לכל המשימות | התאם timeout לאופי המשימה |

- [ ] תלות חיצונית לא מגיבה
- [ ] סומן לחקירה / הופעל graceful-stop
