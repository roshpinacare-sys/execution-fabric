# מדריך פתרון תקלות נפוצות: תורים תקועים, כשלי שרשרת והעברות ממתינות

> נכתב מתוך ניתוח 280 כשלי שרשרת ו-36 משימות כושלות — תרחישים שחוזרים על עצמם במציאות.

---

## 1. תור תקוע: משימות לא מתקדמות מ-PENDING

### סימפטומים
- משימות נשארות ב-PENDING מעל 10 דקות
- Workers מדווחים IDLE אבל התור לא מתרוקן
- `/api/metrics` מראה `queueDepth` עולה

### אבחון מהיר (קונסולה)
```bash
# בדיקת מצב תורים
curl -s /api/metrics | jq '.queues[] | select(.depth > 0)'

# בדיקת Workers זמינים
curl -s /api/census | jq '.workers[] | select(.status == "IDLE")'

# חיפוש שגיאות בלוגר האחרון
curl -s /api/evolution/logs?limit=50 | jq '.[] | select(.level == "ERROR")'
```

### סיבות נפוצות ותיקון
| סיבה | זיהוי | תיקון |
|-------|-------|-------|
| Worker קרס בלי לדווח | `lastHeartbeat` > 60 שניות | `POST /api/tasks/{id}/requeue` — מחזיר לתור |
| תלות חסרה (כלי/סקריפט) | שגיאת `ENOENT` בלוגים | התקן חסר: `npm i -g @saos/arsenal` או הוסף ל-PATH |
| הגבלת מקביליות נמוכה | `concurrency: 1` בקונפיג | הגדל ב-`dispatch.config.json`: `"concurrency": 4` |
| תור עדיפות חוסם | משימות HIGH תקועות לפני LOW | `POST /api/queues/rebalance` — מאזן מחדש |

### מניעה
- הגדר `heartbeatTimeout: 30000` ב-dispatch config
- הפעל `queueHealthCheck` כל 60 שניות (מובנה בגרסה 2.1+)

## 2. כשל שרשרת (Ledger): בלוק לא נחתם / Hash mismatch

### סימפטומים
- `chain.failed` עולה ב-/api/metrics
- שגיאת `HASH_MISMATCH` או `SIGNATURE_INVALID` בלוגים
- בלוקים חדשים לא מופיעים ב-`GET /api/chain/tip`

### אבחון מהיר
```bash
# מצב שרשרת נוכחי
curl -s /api/metrics | jq '.chain'

# בלוק אחרון תקין
curl -s /api/chain/tip

# בלוקים כושלים אחרונים
curl -s /api/chain/failed?limit=10
```

### סיבות נפוצות ותיקון
| סיבה | זיהוי | תיקון |
|-------|-------|-------|
| שעון מערכת לא מסונכרן | `timestamp` בבלוק עתידי/עבר > 5 שניות | `sudo chronyc makestep` או `ntpdate -s pool.ntp.org` |
| מפתח חתימה פג/השתנה | `pubkey` לא תואם `genesis.json` | שחזר `keys/signer.pem` מגיבוי; עדכן `genesis.json` |
| זיכרון מלא — כתיבה חלקית | `ENOSPC` או `EIO` בלוגים | פנה מקום: `df -h /var/lib/saos/ledger`; הפעל `ledger compact` |
| תחרות כתיבה (race) | שני תהליכים כותבים לאותו קובץ | ודא `singleWriter: true` ב-`ledger.config.json` |

### שחזור מהיר
```bash
# 1. עצור כותב שרשרת
systemctl stop saos-ledger-writer

# 2. אמת תקינות
saos-ledger verify --full

# 3. אם תקין — הפעל מחדש
systemctl start saos-ledger-writer

# 4. אם פגום — שחזר מנקודת-בדיקה אחרונה
saos-ledger restore --checkpoint=latest
```

## 3. הצעות העברה (Handoffs) ממתינות מעל 6 שעות

### סימפטומים
- התראת "השער-ממתין-ריבוני" בקונסולה
- `GET /api/handoffs/pending` מחזיר פריטים עם `ageHours > 6`
- אין פעילות ב-`/api/evolution/logs` עבור ה-handoff

### אבחון מהיר
```bash
# רשימת הממתינים
curl -s /api/handoffs/pending | jq '.[] | {id, repo, ageHours, author}'

# בדיקת סטטוס CI/CD חיצוני
curl -s /api/handoffs/{id}/checks

# היסטוריית החלטות
curl -s /api/handoffs/{id}/history
```

### סיבות נפוצות ותיקון
| סיבה | זיהוי | תיקון |
|-------|-------|-------|
| בדיקות CI נכשלות | `checks.status == "FAILED"` | פתח לוגי CI; תקן קוד; דחוף מחדש — ה-handoff יתעדכן אוטומטית |
| סתירת מיזוג (merge conflict) | `checks.mergeable == false` | `git fetch origin && git merge-base --is-ancestor HEAD origin/main` — פתר ידני |
| מדיניות סקירה לא מתקיימת | `requiredApprovers: 2` אבל רק 1 | בקש סקירה נוספת או עדכן מדיניות ב-`handoff.policy.json` |
| כלי אוטומטי לא הגיב | אין `bot-review` ב-history אחרי 30 דק' | הפעל מחדש: `POST /api/handoffs/{id}/retrigger-bot` |

### פעולה מהירה (אם דחוף)
```bash
# אישור ידני עם עקיפה (דורש הרשאת ריבון)
POST /api/handoffs/{id}/approve {
  "override": true,
  "reason": "CI ירוק, סקירה ידנית בוצעה, חריגת זמן"
}

# פריסה מיידית אחרי אישור
POST /api/handoffs/{id}/deploy
```

## 4. Worker מדווח שגיאה חוזרת: "Module not found" / "Permission denied"

### סימפטומים
- אותו Worker נכשל שוב ושוב עם אותה שגיאה
- `task.attempts` עולה, `maxRetries` מושג
- משימה עוברת ל-FAILED סופית

### אבחון
```bash
# פרטי משימה כושלת
curl -s /api/tasks/{id} | jq '{id, status, attempts, error, workerId}'

# סביבת Worker
curl -s /api/census/workers/{workerId} | jq '.env, .cwd, .nodeVersion'

# השוואה ל-Worker תקין
curl -s /api/census/workers | jq '.[] | select(.status=="OK") | .env'
```

### תיקון לפי שגיאה
| שגיאה | סיבה | תיקון |
|--------|-------|-------|
| `MODULE_NOT_FOUND` | `node_modules` חסר / גרסה לא תואמת | `cd /workspace && npm ci` או הוסף `NODE_PATH` |
| `EACCES: permission denied` | הרשאות קובץ/תיקייה | `chown -R saos:saos /workspace && chmod -R 755 /workspace` |
| `ENOENT: no such file` | נתיב יחסי שגוי | תקן `cwd` ב-`worker.config.json` או השתמש בנתיבים מוחלטים |
| `SIGKILL` / `OOM` | זיכרון נגמר | הגדל `memoryLimit` ב-worker config; בדוק דליפות עם `node --inspect` |

## 5. צ'ק-ליסט אבחון מהיר (הדבק לקונסולה)

```bash
# הרץ כשרשרת — מחזיר סיכום בריאות ב-30 שניות
curl -s /api/metrics | jq '{chain: .chain, queues: .queues | map({name, depth, rate}), workers: .workers | map({id, status, load}), handoffs: .handoffs.pending}'
```

**קריאה לפעולה**: אם אחד המדדים לעיל חורג — התחל מהסעיף המתאים במדריך זה. רוב התקלות נפתרות ב-2-3 פקודות.

## נספח: קודי שגיאה נפוצים ומשמעותם

| קוד | משמעות | פעולה ראשונה |
|-----|---------|----------------|
| `CHAIN_HASH_MISMATCH` | בלוק לא תואם שרשרת | `saos-ledger verify` |
| `QUEUE_STALLED` | תור לא מתקדם | בדוק Workers + `requeue` |
| `HANDOFF_STALE` | הממתין > 6 שעות | בדוק CI + אישור ידני |
| `WORKER_UNHEALTHY` | ללא heartbeat | `requeue` משימות + הפעל מחדש Worker |
| `SIGNATURE_INVALID` | מפתח לא תואם | שחזר מפתח חתימה |
| `RESOURCE_EXHAUSTED` | דיסק/זיכרון/CPU | פנה משאבים / הגדל מגבלות |
