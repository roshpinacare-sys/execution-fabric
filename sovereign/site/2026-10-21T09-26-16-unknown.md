# לקחים מעשיים: ניהול כשלי "unknown" בשרשרת-האמת — אבחון, תיקון ומניעה

# לקחים מעשיים: ניהול כשלי "unknown" בשרשרת-האמת

> **הקשר**: 25 רשומות `FAILED` עם `errorClass: "unknown"` מופיעות בשרשרת (ראו `worthALook`). הכשל אינו חושף סוג שגיאה ספציפי — לכן נדרש תהליך אבחון מובנה.

---

## 1️⃣ זיהוי מהיר (≤ 2 דקות)
| פעולה | פקודה / מקום | מה מחפשים |
|--------|---------------|------------|
| סינון כשלי unknown | `GET /api/chain?status=FAILED&errorClass=unknown` | רשימת ה-hash-ים, timestamps, `workerId` |
| בדיקת payload גולמי | `GET /api/chain/<hash>/raw` | שדות `error.message`, `error.stack`, `context` |
| הצלבת worker | `GET /api/workers/<workerId>/recent` | האם אותו worker נכשל שוב? |
| בדיקת תלות חיצונית | לוגי רשת / ספק API | נפילת שירות, rate-limit, schema שבור |

**סימן אדום**: אם `error.message` ריק או `"Unknown error"` — הבעיה לרוב ב-**serialization** או **timeout שקט**.

---

## 2️⃣ אבחון עומק (≤ 10 דקות)
1. **השוואת סכימה** — ודא שה-`payload` תואם את `TaskSchema` העדכני (`/api/arsenal/schemas`).
2. **בדיקת timeout** — חפש `durationMs > 30000` ברשומת השרשרת; עובדים שנחסמים >30 שניות נרשמים כ-unknown.
3. **זיכרון/משאבים** — `GET /api/metrics?worker=<id>&window=5m` → `memory.rss`, `eventLoopLag`.
4. **גרסת קוד** — `worker.version` מול `HEAD` הנוכחי; פער גרסאות = באג שתוקן כבר.
5. **לוגי קונסולה** — `journalctl -u saos-worker-<id> --since "-15 min" | grep -i error`.

---

## 3️⃣ תיקון מיידי (Runbook)
| תרחיש | פעולה מתקנת | פקודה / API |
|---------|--------------|--------------|
| Payload לא תקין | דחיית משימה חוזרת עם payload מתוקן | `POST /api/tasks/retry {hash, correctedPayload}` |
| Timeout | הגדלת `timeoutMs` ב-task-def או פיצול למשימות-בנות | `PATCH /api/tasks/def/<id> {timeoutMs: 60000}` |
| גרסה ישנה | פריסה מחודשת של ה-worker | `POST /api/workers/<id>/redeploy` |
| שירות חיצוני נפל | המתנה + retry אוטומטי (backoff אקספוננציאלי) | מובנה ב-worker v2.3+ |
| באג קוד ידוע | החלת hotfix + בנייה מחדש | `git apply <patch> && npm run build:workers` |

> **טיפ**: לאחר תיקון — סמן את הרשומה כ-`RESOLVED` בשרשרת: `PATCH /api/chain/<hash> {resolution: "<סיבה>", resolvedBy: "<מפעיל>"}`.

---

## 4️⃣ מניעה לטווח ארוך
- **הוספת errorClass מפורש** בכל `catch` ב-workers — לעולם לא `throw new Error(e)` בלי סיווג.
- **Middleware אבחון אוטומטי** — עוטף כל הרצת משימה, לוכד stack מלא, מצמיד `errorClass` לפי regex.
- **התראת סף** — אם `unknown > 5` בחלון 1 שעה → התראת Slack/Telegram אוטומטית.
- **סקירת כשלים שבועית** — חלק מ-"מדדי-ביצועים שבועיים" (כבר קיים כ-improvement).
- **תיעוד תבניות** — הוסף לקובץ זה כל תבנית חדשה שמתגלה (למשל: `"ECONNRESET → network-unknown"`).
