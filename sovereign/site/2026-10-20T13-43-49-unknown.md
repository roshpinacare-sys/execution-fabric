# מדריך אבחון ותיקון: כשלים חוזרים במחלקת "unknown"

## רקע
בשרשרת האמת נרשמו **25 כשלים** שסווגו תחת המחלקה `unknown` — מחלקת שגיאה שאינה חושפת את סיבת הכשל האמיתית. מדריך זה מספק מסגרת שיטתית לאבחון, תיקון ומניעה.

---

## 1. דפוסי זיהוי נפוצים

| דפוס | סימנים בזמן ריצה | סיבה שורשית סבירה |
|-------|------------------|----------------------|
| **החרגה לא-מטופלת ב-Worker** | הלוג נעצר בפתאומיות, אין stack trace גלוי | `try/catch` חסר סביב קוד אסינכרוני |
| **Timeout שקט** | המשימה נתקעת ב-RUNNING עד סף זמן, ואז נכשלת | חסר `AbortSignal` או הגדרת timeout מפורשת |
| **כשל סריאליזציה** | payload מכיל `undefined`/`Symbol`/פונקציה | חסר `JSON.stringify` עם replacer מותאם |
| **שגיאת רשת חולפת** | כשל אקראי, חוזר בהרצה חוזרת | חסר retry עם backoff אקספוננציאלי |
| **הפרת חוזה קלט** | validation עובר אבל הריצה נכשלת | סכמה רופפת מדי / חסר runtime validation |

## 2. תהליך אבחון שלב-אחר-שלב

### שלב א': איסוף הקשר מלא
```bash
# בקונסולה — סינון כשלי unknown אחרונים
curl -s /api/metrics | jq '.failures[] | select(.class=="unknown") | {id, taskId, timestamp, workerId, payload}'
```

### שלב ב': שחזור מקומי
1. העתק את `taskId` הרלוונטי
2. הרץ מחדש עם דגל דיבוג: `SAOS_DEBUG=1 npm run worker -- --task=<id>`
3. לכוד stack trace מלא

### שלב ג': מיפוי לסיווג מדויק
עדכן את קוד הסיווג ב-`src/lib/failure-classifier.ts`:
```typescript
// לפני: החזרת 'unknown' כברירת מחדל
export function classifyFailure(err: Error): FailureClass {
  if (err.name === 'TimeoutError') return 'timeout';
  if (err.code === 'ECONNRESET') return 'network-transient';
  if (err instanceof ValidationError) return 'contract-violation';
  // ... הוסף תנאים ספציפיים
  return 'unknown'; // רק כמוצא אחרון
}
```
