# כרטיס משימת העברה: פעולות מהירות (Approve/Reject) עם משוב מיידי

# הצעה: פעולות מהירות בכרטיס משימת העברה

## הבעיה
כרגע יש 3 הצעות העברה ממתינות לאישור (9-10 שעות). בקונסולת ה-RTL, כרטיס משימה מסוג `handoff` מציג מידע אך דורש ניווט למסך נפרד או שימוש ב-CLI לאישור/דחייה. זה יוצר חיכוך מיותר בפעולה השכיחה והקריטית ביותר — החלטת ריבון על פריסה.

## הפתרון
להוסיף **שורת פעולות ראשית (Primary Action Bar)** בתחתית כרטיס משימת `handoff` בקונסולה:

- **כפתור "אשר פריסה"** — ראשי, ירוק, אייקון ✓
- **כפתור "דחה"** — משני, אדום, אייקון ✗
- **מצב טעינה** — ספינר + טקסט "מאשר..." / "דוחה..." לאחר לחיצה
- **אישור משני (Modal)** — רק לדחייה: "האם אתה בטוח? פעולה זו תחזיר את ההצעה למצב pending."

## מיקום בקוד
`apps/console/src/components/TaskCard/TaskCard.tsx` (או המקביל לכרטיס משימה) — להוסיף בלוק `handoffActions` שמוצג רק כש־`task.type === 'handoff' && task.status === 'PENDING_APPROVAL'`.

## API קיים לשימוש
- `POST /api/handoffs/:id/approve` — מאשר פריסה
- `POST /api/handoffs/:id/reject` — דוחה הצעה

שניהם מחזירים `{ ok: true, task: Task }` ומעדכנים את השרשרת.

## התנהגות UX
1. לחיצה על "אשר" → מצב טעינה → רענון כרטיס אוטומטי → טוסט "הפריסה אושרה והועברה לביצוע"
2. לחיצה על "דחה" → מודל אישור → מצב טעינה → רענון → טוסט "ההצעה נדחתה, סטטוס חזר ל-pending"
3. מקלדת: `Enter` = אשר, `Escape` = סגור מודל/בטל
4. נגישות: `aria-label`, פוקוס נראה, ניגודיות WCAG AA

## מדד הצלחה
- זמן ממוצע מהצגת כרטיס להחלטה < 30 שניות (כיום ~2-3 דקות עקב ניווט)
- אפס אישורים שגויים (בזכות מודל האישור לדחייה)
- נראות: 100% מהכרטיסים הממתינים מציגים פעולות זמינות מיידית

## למה עכשיו
שלוש הצעות ממתינות 9+ שעות — זה צוואר בקבוק ריבוני. שיפור נקודתי זה מחזיר שליטה מיידית לבעלים בלי לשנות ארכיטקטורה.
