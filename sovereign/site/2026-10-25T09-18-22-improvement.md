# מדריך שאלות-ותשובות: אבחון ופתרון תקלות נפוצות ברשת-הביצוע

# מדריך שאלות-ותשובות: אבחון ופתרון תקלות נפוצות ברשת-הביצוע

> **למי זה מיועד:** מפעילי קונסולה RTL, מפתחי Workers, וכל מי שצריך להחזיר את הרשת למסלול תוך דקות.
> **מבנה:** כל סעיף = שאלה נפוצה → סיבה שורשית → אבחון מהיר (פקודות/בדיקות) → תיקון מיידי → מניעה.

---

## 1. "למה המשימה שלי תקועה על `UNKNOWN` ב-Ledger?"

**סיבה שורשית:** Worker החזיר קוד יציאה לא-סטנדרטי או קרס לפני כתיבת `result.json`. ה-Ledger רושם `unknown` כברירת-מחדל כשאין payload תקין.

**אבחון מהיר:**
```bash
# בקונסולה RTL → כרטיס "שרשרת-אמת" → סנן status=unknown
# או ב-API:
curl -s /api/ledger?status=unknown | jq '.entries[] | {hash, worker, exitCode, stderr}'
```

**תיקון מיידי:**
1. פתח את ה-hash הרלוונטי → בדוק `stderr` ו-`exitCode`.
2. אם `exitCode=137` → OOM Kill. הגדל `memoryLimit` ב-manifest של ה-Worker.
3. אם `exitCode=1` + stack trace → באג בקוד ה-Worker. תקן והפעל מחדש דרך `Dispatch → Retry`.
4. אם אין `stderr` כלל → ה-Worker לא כתב ל-stdout/stderr. הוסף לוגינג מינימלי (`console.error`/`eprintln`).

**מניעה:** הוסף ולידציית יציאה ב-wrapper של ה-Worker: `process.on('exit', code => { if (code !== 0) logger.fatal({exitCode: code}, 'non-zero exit') })`.

## 2. "ה-Dispatch לא שולח משימות ל-Workers — התור גדל אבל `activeWorkers=0`"

**סיבה שורשית:** Circuit Breaker פתוח עקב רצף כשלים קודם, או שכל ה-Workers במצב `COOLDOWN` אחרי `MAX_RETRIES`.

**אבחון מהיר:**
```bash
# בקונסולה: כרטיס "לוח-משימות" → בדוק עמודת "Circuit Breaker"
curl -s /api/metrics | jq '.circuitBreaker, .workers[] | {id, status, cooldownUntil}'
```

**תיקון מיידי:**
- אם Circuit Breaker פתוח: `POST /api/dispatch/circuit-breaker/reset` (רק אחרי שווידאת שסיבת הכשל תוקנה).
- אם Workers ב-COOLDOWN: המתן או `POST /api/workers/{id}/wake` להערה ידנית.

**מניעה:** כוונן `circuitBreaker.threshold` ו-`cooldownMs` ב-`config/dispatch.yaml` לפי עומס אמיתי, לא ברירת-מחדל.

## 3. "מדד `backpressure` קופץ ל-1.0 וה-throughput צונח לאפס"

**סיבה שורשית:** ה-Dispatch מייצר משימות מהר יותר מה-Workers מסוגלים לצרוך. ה-backpressure מופעל ב-`queueDepth > highWatermark`.

**אבחון מהיר:**
```bash
curl -s /api/metrics | jq '{queueDepth, highWatermark, backpressure, throughputPerMin}'
# בקונסולה: כרטיס "מדדי רשת" → גרף backpressure בזמן אמת
```

**תיקון מיידי:**
1. **הקטן קצב ייצור:** `POST /api/dispatch/rate-limit { "maxPerMinute": 50 }`
2. **הגדל צריכה:** הוסף Workers זמניים (`POST /api/workers/spawn { "count": 3, "profile": "heavy" }`)
3. **נקה תור:** `POST /api/dispatch/queue/purge-stale { "olderThanMinutes": 60 }`

**מניעה:** הפעל Auto-scaling: `dispatch.autoScale.enabled=true` עם `scaleUpTrigger: "backpressure > 0.7 for 5m"`.

## 4. "ה-Ledger מראה `hash mismatch` באימות — האם הנתונים נפגמו?"

**סיבה שורשית:** 99% מהמקרים = באג ב-client שכותב ל-Ledger (סדר שדות JSON שונה, timestamp לא דטרמיניסטי). 1% = השחתה אמיתית.

**אבחון מהיר:**
```bash
# הרץ אימות מקומי על ה-entry החשוד:
npx @execution-network/ledger-verify --hash <HASH> --verbose
# השווה `canonicalJSON` מול `storedJSON`
```

**תיקון מיידי:**
- אם הבדל בסדר שדות/רווחים → תקן את ה-serializer ב-client (השתמש ב-`canonical-json` library).
- אם השחתה אמיתית → `POST /api/ledger/quarantine { "hash": "...", "reason": "corruption" }` והפעל `ledger-repair` מה-CLI.

**מניעה:** הוסף pre-commit hook שמריץ `ledger-verify` על כל entry חדש בסביבת פיתוח.

## 5. "ה-Worker מדווח `ENOENT: no such file or directory` על קובץ שברור שקיים"

**סיבה שורשית:** נתיב יחסי שנפתר מול `cwd` שגוי. ה-Dispatch מריץ Workers ב-`/var/lib/execution/tasks/{taskId}/` — לא בספריית הפרויקט.

**אבחון מהיר:**
```bash
# בדוק manifest של ה-Worker:
cat /etc/execution/workers/<worker-id>/manifest.yaml | grep -A5 workingDir
# לוג ה-Worker מראה cwd:
jq -r '.cwd' /var/log/execution/worker-<id>.log
```

**תיקון מיידי:**
- ב-manifest: הגדר `workingDir: "/var/lib/execution/tasks/${TASK_ID}"` או השתמש בנתיבים מוחלטים בלבד.
- בקוד: `const base = process.env.TASK_WORKDIR || process.cwd();`

**מניעה:** תבנית Worker סטנדרטית (`worker-template`) עם `workingDir` מוגדר נכון.

## 6. "למה ה-`/api/evolution` מראה `openLoops=13` ולא יורד?"

**סיבה שורשית:** 13 ממצאי HIGH פתוחים מביקורות-עצמיות (ראו `worthALook`). לולאת הלמידה מעכלת בקצב התקציב — כל ממצא דורש החלטת בעלים (אימוץ/דחייה/דחייה-זמנית).

**אבחון מהיר:**
```bash
curl -s /api/evolution/open-highs | jq '.[] | {id, title, severity, ageDays, ownerDecision}'
```

**תיקון מיידי:**
- עבור כל ממצא: החלט → `POST /api/evolution/highs/{id}/decision { "action": "adopt|defer|reject", "reason": "..." }`
- אימוץ = נוצר Improvement אוטומטי. דחייה = נסגר עם נימוק.

**מניעה:** הקצה 30 דק'/שבוע ל"סגירת לולאות" — עובר על הרשימה ומקבל החלטות.

## 7. "הקונסולה RTL לא נטענת במובייל — כרטיסים חורגים מהמסך"

**סיבה שורשית:** Grid CSS קבוע (`grid-template-columns: repeat(3, 1fr)`) בלי breakpoint למובייל.

**אבחון מהיר:**
```bash
# פתח DevTools → Device Toolbar → iPhone SE
# בדוק כרטיס "לוח-משימות" ו-"שרשרת-אמת"
```

**תיקון מיידי:**
```css
/* console/src/styles/cards.grid.css */
.cards-grid {
  display: grid;
  grid-template-columns: 1fr;
  gap: 1rem;
}
@media (min-width: 640px) { .cards-grid { grid-template-columns: repeat(2, 1fr); } }
@media (min-width: 1024px) { .cards-grid { grid-template-columns: repeat(3, 1fr); } }
```

**מניעה:** בדיקת רספונסיביות ב-CI (`playwright --project=mobile`).

## 8. "איך מעבירים קוד מ-git ל-Dispatch בלי לשבור את ה-handoff?"

**סיבה שורשית:** ה-handoff מצפה ל-`manifest.yaml` חתום ו-`artifact.tar.gz` עם checksum תואם. קומיט ישיר בלי בנייה שובר את השרשרת.

**אבחון מהיר:**
```bash
# בדוק סטטוס handoff אחרון:
curl -s /api/handoffs/latest | jq '{status, manifestHash, artifactHash, errors}'
```

**תיקון מיידי:**
```bash
# תהליך תקין:
./scripts/build-and-sign.sh          # מייצר artifact + manifest חתום
./scripts/handoff-push.sh            # מעלה ל-/api/handoffs עם אימות
```

**מניעה:** Git hook `pre-push` שמריץ `build-and-sign` ובודק `handoff-verify` לפני push ל-main.

## 9. "ה-`/api/census` מראה Workers "זומבים" — רשומים אבל לא מדווחים heartbeat"

**סיבה שורשית:** Worker קרס/נכבה בלי לשלוח `deregister`. ה-census שומר רישום עד `ttlSeconds` (ברירת-מחדל 300s).

**אבחון מהיר:**
```bash
curl -s /api/census | jq '.workers[] | select(.status=="zombie") | {id, lastHeartbeat, ttlRemaining}'
```

**תיקון מיידי:**
- ניקוי ידני: `POST /api/census/cleanup-zombies`
- בדוק למה קרס: לוגים ב-`/var/log/execution/worker-<id>.log`

**מניעה:** `worker.watchdog.enabled=true` ב-config — שולח heartbeat כל 10s ו-auto-deregister ביציאה נקייה.

## 10. "איך מוסיפים מדד מותאם אישית ל-`/api/metrics` בלי לפרוץ את הסכימה?"

**סיבה שורשית:** סכימת המטריקות סגורה (`metrics.schema.json`). הוספת שדה חדש דורשת גרסה חדשה.

**אבחון מהיר:**
```bash
cat config/metrics.schema.json | jq '.properties'
```

**תיקון מיידי:**
1. צור `metrics.schema.v2.json` עם השדה החדש ב-`customMetrics` object.
2. עדכן `config/metrics.yaml`: `schemaVersion: 2`
3. הרץ `./scripts/metrics-migrate.sh v2`
4. פרוס Workers חדשים שקוראים `metrics.emitCustom('myMetric', value)`

**מניעה:** תהליך RFC קליל לכל מדד חדש — PR ל-`metrics.schema.json` עם תיאור, יחידות, ודוגמה.

## 11. "למה ה-`Improvements Wall` לא מראה את השיפור שרק יצרתי?"

**סיבה שורשית:** ה-Wall מציג רק improvements עם `status=DELIVERED`. שיפורים חדשים מתחילים ב-`PROPOSED` → `ACCEPTED` → `IN_PROGRESS` → `DELIVERED`.

**אבחון מהיר:**
```bash
curl -s /api/improvements?status=PROPOSED | jq '.[] | {title, status, createdAt}'
```

**תיקון מיידי:**
- קדם את השיפור: `POST /api/improvements/{id}/advance { "status": "ACCEPTED" }` (דורש הרשאת Owner).
- או המתן לאישור אוטומטי (אם עובר בדיקות CI).

**מניעה:** הגדר `autoAccept: true` ל-CONTENT/DATA improvements שעוברים lint + test.

## 12. "איך מאפסים את הרשת למצב נקי בלי לאבד את ה-Ledger?"

**סיבה שורשית:** לפעמים צריך "hard reset" של Dispatch + Workers + Census — אבל ה-Ledger (hash-chain) הוא שרשרת-אמת ואסור למחוק.

**אבחון מהיר:**
```bash
# ודא גיבוי Ledger:
ls -la /var/lib/execution/ledger/ | head -5
```

**תיקון מיידי:**
```bash
# סדר פעולות בטוח:
1. systemctl stop execution-dispatch execution-workers
2. redis-cli FLUSHDB          # מנקה תורים, קאש, circuit breaker
3. rm -rf /var/lib/execution/tasks/*  # מנקה workdirs
4. POST /api/census/cleanup-zombies
5. systemctl start execution-dispatch execution-workers
6. ודא: curl -s /api/health | jq '.status == "healthy"'
```

**מניעה:** סקריפט `./scripts/hard-reset.sh` שעושה את הנ"ל עם אישור אינטראקטיבי.
