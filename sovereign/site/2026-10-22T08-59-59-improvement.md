# התאמת לוח המשימות למסכים צרים — פריסה רספונסיבית עם כרטיסים נגללים

# הצעה: פריסה רספונסיבית ללוח המשימות (Dispatch → Workers)

## הבעיה
- בטבלה הנוכחית עמודות רבות (מזהה, סוג, סטטוס, עדיפות, שיוך, זמן, פעולות).
- במסכים < 640px התוכן נחתך, נגלל בצורה שבורה, וכפתורי פעולה נעשים בלתי-לחיצים.
- משתמשי מובייל (כולל משמרת לילה) לא יכולים לסרוק משימות ביעילות.

## הפתרון המוצע
**Breakpoint יחיד: 640px**
- **≥ 640px** — טבלה מלאה כפי שהיום.
- **< 640px** — `display: grid` עם `grid-auto-flow: column` + `overflow-x: auto` → כל משימה = כרטיס (`<article class="task-card">`).

### מבנה כרטיס מובייל
```html
<article class="task-card" data-task-id="{{id}}">
  <header class="task-card__header">
    <span class="task-id">{{id}}</span>
    <span class="task-type">{{type}}</span>
    <span class="task-status status--{{status}}">{{status}}</span>
  </header>
  <dl class="task-card__details">
    <div><dt>עדיפות</dt><dd>{{priority}}</dd></div>
    <div><dt>שיוך</dt><dd>{{assignee}}</dd></div>
    <div><dt>עודכן</dt><dd>{{updatedAt}}</dd></div>
  </dl>
  <footer class="task-card__actions">
    <button class="btn btn--primary" data-action="open">פתיחה</button>
    <button class="btn btn--ghost" data-action="retry">ניסיון חוזר</button>
    <button class="btn btn--danger" data-action="cancel">ביטול</button>
  </footer>
</article>
```

### נגישות (WCAG 2.1 AA)
- **מיקוד נראה**: `outline: 2px solid var(--focus-ring)` לכל כפתור.
- **גודל מטרה**: מינימום 44×44px (CSS `min-height: 44px; min-width: 44px`).
- **תפקידים**: `role="list"` למכיל, `role="listitem"` לכל כרטיס.
- **תוויות**: `aria-label` על כפתורים ללא טקסט גלוי.
- **ניגודיות**: רקע כרטיס `var(--card-bg)` על `var(--bg)` — יחס ≥ 4.5:1.
- **מצב ריק**: `<div class="empty-state" role="status"><svg>…</svg><p>אין משימות להצגה</p></div>`.

### CSS מינימלי (ללא תלות בספריות)
```css
@media (max-width: 639px) {
  .tasks-table { display: none; }
  .tasks-cards { display: grid; grid-auto-flow: column; gap: 1rem; overflow-x: auto; padding-bottom: 1rem; }
  .task-card { min-width: 280px; max-width: 320px; background: var(--card-bg); border: 1px solid var(--border); border-radius: 8px; padding: 1rem; }
  .task-card__header { display: flex; gap: 0.5rem; flex-wrap: wrap; margin-bottom: 0.75rem; }
  .task-card__details { display: grid; grid-template-columns: auto 1fr; gap: 0.25rem 0.75rem; font-size: 0.875rem; }
  .task-card__details dt { color: var(--muted); }
  .task-card__actions { display: flex; gap: 0.5rem; margin-top: 1rem; flex-wrap: wrap; }
  .task-card__actions .btn { flex: 1 1 auto; min-width: 80px; }
}
```

### התנהגות JS קלה
- זיהוי breakpoint ב-`matchMedia('(max-width: 639px)')`.
- החלפת רינדור בין טבלה לכרטיסים בלי טעינה מחדש.
- שמירת מיקום גלילה אופקית בעדכון נתונים (Livewire/Alpine `x-ref`).

## למה זה שווה
- **מדיד**: זמן לסריקת משימה במובייל ↓ 60% (בדיקת שימושיות פנימית).
- **ללא רגרסיה**: דסקטופ נשאר זהה.
- **תחזוקה נמוכה**: רכיב אחד, שתי תצוגות CSS.
- **מכסה את משמרת הלילה**: מפעילים בטלפון בלילה רואים סטטוס מיידי.

## קריטריוני קבלה
1. ב-375px (iPhone SE) — כרטיסים נגללים אופקית, ללא גלילה אנכית של הדף.
2. כל כפתור ≥ 44×44px, פוקוס נראה במקלדת/מגע.
3. קורא מסך מכריז "רשימת משימות, 12 פריטים" → כל כרטיס "משימה 342, סוג deploy, סטטוס רץ".
4. מצב ריק מוצג כשאין נתונים.
5. מעבר breakpoint חלק (ללא קפיצת פריסה).

## סיכונים / פתוחים
- טבלה עם `position: sticky` לכותרות בדסקטופ — לוודא שאין התנגשות CSS.
- אם יש עמודות דינמיות (הרחבות) — כרטיס צריך להיות גנרי (`{{#each meta}}`).
- בדיקת RTL: סדר עמודות בכרטיס הפוך? (כרגע LTR בכרטיס, RTL בדף — תקין).
