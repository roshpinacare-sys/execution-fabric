# התאמת כרטיסי שרשרת-אמת ומשימות למובייל: פריסה רספונסיבית, נגישות מקלדת/קורא-מסך ומחוות מגע

# הצעה: התאמת כרטיסי שרשרת-אמת ומשימות למובייל

## הקשר
הקונסולה RTL כבר כוללת כרטיסים אינטראקטיביים לשרשרת-האמת (Ledger) וללוח-המשימות (Dispatch). בפועל, במכשירים צרים (< 640px) הכרטיסים נחתכים, פעולות מוסתרות, וניווט מקלדת/קורא-מסך חסר — מה שמונע שימוש מבצעי מהשטח.

## מה משתנה
| רכיב | מצב נוכחי | מצב מוצע |
|-------|------------|-----------|
| **פריסת כרטיס Ledger** | טבלה אופקית קבועה | Grid רספונסיבי: 1 עמודה במובייל, 2 בטאבלט, 4 בדסקטופ; שדות משניים מתקפלים ל-accordion |
| **פריסת כרטיס משימה** | כרטיס רחב עם כפתורי פעולה בצד | כרטיס מחסנית (stack) במובייל; כפתורי פעולה ראשיים בולטות, משניות ב-overflow menu |
| **ניווט מקלדת** | Tab order שבור, אין focus-visible | Tab לוגי RTL, `focus-visible` מודגש, `Enter`/`Space` מפעילים, `Esc` סוגר תפריטים |
| **תוויות ARIA** | חסרות ברוב הכפתורים והאקורדיונים | `aria-label`/`aria-labelledby` בעברית לכל פעולה; `aria-expanded`/`aria-controls` לאקורדיונים |
| **מחוות מגע** | אין | Swipe ימינה (RTL) על כרטיס → חושף תפריט פעולות (העתק hash, פתח פרטים, סמן תקלה); Swipe שמאלה → סגירה |
| **מצב ניגודיות גבוהה** | לא קיים | מתג בהגדרות קונסולה → CSS custom properties מחליפים צבעים ל-WCAG AAA (יחס 7:1) |
| **הכרזת סטטוס חי** | לא מוכרז לקוראי-מסך | `aria-live="polite"` על מונה כשלים/ממתינים; עדכון בלי איבוד פוקוס |

## למה זה חשוב
- **מבצעיות**: מפעילי משמרת-לילה וצוותי שטח משתמשים בטלפונים/טאבלטים — היום הם "עיוורים" לתקלות.
- **נגישות חוקית**: עמידה ב-WCAG 2.1 AA (מינימום) ו-AAA (ניגודיות) נדרשת לגופים ציבוריים/ביטחוניים.
- **אחידות**: אותו קוד משרת דסקטופ ומובייל — פחות באגים, תחזוקה קלה.

## איך לממש (תכנית טכנית)
1. **CSS Grid + Container Queries** — להחליף `flex` ב-`grid-template-columns: repeat(auto-fit, minmax(280px, 1fr))` בכרטיסים; להשתמש ב-`@container` לשבירת עמודות פנימית.
2. **רכיב `ResponsiveCard` משותף** — wrapper המקבל `fields: {primary, secondary, actions}` ומטפל בפריסה, אקורדיון, overflow menu.
3. **Hook `useKeyboardNavigation`** — מנהל roving tabindex בתוך רשימת כרטיסים, תומך חיצים ימין/שמאל (RTL) ו-Home/End.
4. **ספריית מחוות קלה** — `touch-action: pan-y; touch-start/x` לחישוב כיוון swipe; הוספת מחלקה `.swipe-open` ל-300ms עם transition.
5. **CSS Custom Properties לערכת צבעים** --
   ```css
   :root { --fg: #1a1a1a; --bg: #fafafa; --border: #ddd; --focus: #0066cc; }
   @media (prefers-contrast: more) { :root { --fg: #000; --bg: #fff; --border: #000; --focus: #000; } }
   .high-contrast { --fg: #000; --bg: #fff; --border: #000; --focus: #ff0; }
   ```
6. **בדיקות אוטומטיות** — Playwright עם `axe-core` לנגישות; viewport 375x667, 768x1024, 1440x900; סימולציית מקלדת וקורא-מסך (NVDA/VoiceOver).

## קריטריוני קבלה (Definition of Done)
- [ ] כרטיס Ledger ומשימה נראים תקין ב-375px, 768px, 1440px (צילומי מסך ב-CI).
- [ ] ניווט מקלדת מלא: Tab, Shift+Tab, חיצים, Enter, Space, Esc — ללא "מלכודות פוקוס".
- [ ] `axe-core` מדווח 0 violations ברמת AA בכל viewport.
- [ ] Swipe חושף/סוגר תפריט פעולות במובייל (iOS Safari, Chrome Android).
- [ ] מצב ניגודיות גבוהה מופעל/מכובה מיידית בלי רענון דף.
- [ ] הכרזות `aria-live` נשמעות ב-NVDA/VoiceOver כשמונה כשלים משתנה.
- [ ] תיעוד רכיב `ResponsiveCard` ב-Storybook עם דוגמאות RTL.

## סיכונים ותלויות
- **סיכון**: Container Queries לא נתמכים בדפדפנים ישנים — פתרון: polyfill או fallback ל-media queries.
- **תלות**: רכיבי UI קיימים (Button, Badge, Icon) כבר תומכים ב-`focus-visible` ו-`aria` — לוודא עקביות.
- **ביצועים**: רשימות ארוכות (מאות כרטיסים) — להשתמש בווירטואליזציה (`react-window` או דומה) בלי לשבור נגישות.
