# מדריך אבחון ותיקון כשלי הרצה במחלקת unknown

## רקע
בשרשרת-האמת נרשמו 21 כשלים שסווגו תחת המחלקה `unknown`. מכיוון שהם חתומים בכנות בשרשרת, הם מהווים חלון אמיתי לתבניות כישלון סמויות. מדריך זה מספק תהליך מובנה לאבחון, סיווג מחדש ותיקון.

---

## שלב 1 — שליפת הרשומות הגולמיות
```bash
curl -s https://<host>/api/ledger/entries \
  | jq '.[] | select(.status=="FAILED" and .department=="unknown")'
```
שמור את הפלט לקובץ `unknown-failures.json` לעבודה חוזרת.

---

## שלב 2 — מיפוי שדות חוזרים
הרץ סקריפט קצר שחולץ שדות מועמדים לסיווג:
```python
import json, collections, re

data = json.load(open('unknown-failures.json'))
for entry in data:
    ctx = entry.get('context', {})
    for key in ['error_code', 'exception_type', 'component', 'route', 'worker_id']:
        if key in ctx:
            print(f'{key}={ctx[key]}')
```
אסוף תדירויות:
```bash
python3 extract.py | sort | uniq -c | sort -rn
```
חפש ערכים שמופיעים ב-≥3 רשומות — אלו המועמדים הראשונים למחלקה חדשה.

## שלב 3 — הגדרת מחלקות חדשות
לכל דפוס שזוהה, צור מחלקה ייעודית ב-`ledger/schema/departments.yaml`:
```yaml
- name: auth_token_expired
  match:
    error_code: "TOKEN_EXPIRED"
  remediation: "רענון אוטומטי של אסימון לפני הרצה חוזרת"
- name: upstream_timeout
  match:
    exception_type: "TimeoutError"
  remediation: "הגדלת timeout והפעלת circuit-breaker"
```
הרץ ולידציה:
```bash
saos ledger validate-schema
```

## שלב 4 — סיווג רטרואקטיבי
עדכן את 21 הרשומות הקיימות:
```bash
saos ledger reclassify --file unknown-failures.json --dry-run
# אחרי אישור:
saos ledger reclassify --file unknown-failures.json --apply
```
הפעולה מוסיפה שדה `department` חדש וחותמת hash מעודכן — השרשרת נשארת שלמה.

## שלב 5 — אוטומציה למניעת הישנות
הוסף ב-`workers/dispatcher/preflight.ts` בדיקת קדם-הרצה:
```typescript
export async function preflightCheck(task: Task): Promise<PreflightResult> {
  const tokenAge = Date.now() - task.context.authIssuedAt;
  if (tokenAge > 55 * 60 * 1000) {
    return { ok: false, department: 'auth_token_expired', reason: 'token near expiry' };
  }
  return { ok: true };
}
```
הגדר כלל התראה ב-`monitoring/alerts.yml`:
```yaml
- name: unknown_failure_spike
  condition: "rate(failed{department='unknown'}[5m]) > 0.1"
  severity: warning
  runbook: "runbooks/unknown-failure-triage.md"
```
